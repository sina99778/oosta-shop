# مسیرهای خرید و بازگشت مشتری

- آیکون سبد خرید در منوی دسکتاپ کنار نام سبد و در نوار موبایل بیرون از منوی کشویی قرار دارد. شمارنده از همان API خصوصی می‌آید و عنوان دسترس‌پذیر شامل تعداد اقلام است.
- لینک ارسال مجدد رسید در جزئیات سفارشِ سبدی پس از رد شدن رسید برای سفارش کارت‌به‌کارت غیربلوبانکی فعال می‌ماند. جزئیات سفارش همچنان به مالک سفارش محدود است. فاکتور منقضی و در انتظار پرداخت، مسیر قبلی را دارد.
- سه صفحهٔ شرایط خرید، ضمانت و حریم خصوصی از فوتر در دسترس‌اند. محتوای منتشرشده در سامانهٔ مدیریت محتوا بر متن پیش‌فرض مقدم است. متن پیش‌فرض شرایط نمایشی هر پلن و مسیر ثبت تیکت را توضیح می‌دهد.
- لینک تلگرام پشتیبانی در فوتر، صفحهٔ اصلی، فهرست و جزئیات محصولات از تنظیمات سایت خوانده می‌شود. خروجی به نشانی HTTPS روی `t.me` و نام کاربری معتبر محدود است.

## بررسی انتشار

- آزمون مرورگر روی نسخهٔ نمایشی در عرض‌های ۳۲۰، ۳۹۰، ۱۰۲۴ و ۱۴۴۰ پیکسل، وجود یک آیکون قابل مشاهده با برچسب دسترس‌پذیر و نبود سرریز افقی در سربرگ را بررسی کرد.
- `npm run verify`، ESLint و بیلد تولید API و وب پاس شدند. هر دو بررسی npm audit با گواهی‌های مورداعتماد سیستم صفر مورد گزارش کردند. آزمون‌های حساب، پرداخت، ارسال ایمیل و تحویل از داده و سرویس آزمایشی استفاده کردند.
- پیش از مهاجرت بازیابی رمز، بکاپ `age` با SHA-256 و باز کردن جریان فشرده با کلید بازیابی محلی بررسی شد. فایل موقت روی VPS حذف شد و دادهٔ بازشده روی دیسک نوشته نشد.
- پیش از انتشار، SMTP روی سرور تنظیم نشده و ارسال ایمیل خاموش بود. فعال شدن ایمیل بازیابی و یادآوری تمدید به تنظیم فرستنده و آزمون تحویل نیاز دارد.
- در تلاش اول، دسترسی پوشه‌های بستهٔ منبع برای پردازهٔ غیر-root محدود بود و بررسی راه‌اندازی وب انتشار را به نسخهٔ قبلی برگرداند. برای آماده‌سازی مجدد، دسترسی خواندن و پیمایش به فایل‌های منبع استخراج‌شده اضافه شد. پیش از فعال‌سازی، دسترسی به تصاویر و فایل‌های مهاجرت از داخل هر تصویر با UID 1000 بررسی شد.
- نسخهٔ `20261121-customer-account` پس از اعمال مهاجرت افزایشی بازیابی رمز و تأیید سلامت دیتابیس، API و وب فعال شد. مسیر عمومی صفحهٔ اصلی، سبد، سه صفحهٔ فوتر و صفحات بازیابی ۲۰۰ بودند. بستهٔ عمومی ورود لینک بازیابی را دارد. شمارندهٔ ناشناس ۴۰۱ و بدون کش بود و مسیر درخواست بازیابی با SMTP خاموش، ۵۰۳ برگرداند. تنظیمات پرداخت، فایل محیطی و تایمرهای بکاپ و بلو همان وضعیت قبلی را داشتند.

## فعال‌سازی ایمیل

- دامنهٔ فرستنده در Resend تأیید شد. SMTP تولید با STARTTLS روی پورت ۵۸۷ فعال شد. کلید از SSH تعاملی ثبت شد و فایل موقت پس از تأیید حذف شد.
- Resend تحویل پیام آزمایشی فرستاده‌شده از کد SMTP داخل کانتینر API را به گیرندهٔ شبیه‌سازی‌شده تأیید کرد. درخواست عمومی بازیابی با نشانی ساختگی پاسخ پذیرش گرفت. آزمون بازیابی در دیتابیس موقت نیز انقضا، مصرف یک‌باره و ابطال نشست‌های قبلی را دوباره تأیید کرد. تحویل لینک بازیابی به صندوق واقعی مشتری در این مرحله آزموده نشد.
- یک پیام قدیمی با گیرندهٔ ساختگی در صف به بررسی دستی منتقل شد. سلامت API، اتصال دیتابیس، صفحهٔ ورود و وضعیت قبلی روش‌های پرداخت پس از راه‌اندازی تأیید شدند.

## جای آیکون سبد خرید

- سربرگ در موبایل و دسکتاپ یک لینک سبد در نوار ابزار دارد. برچسب دسترس‌پذیر، شمارنده و کنترل دسترسی API سبد حفظ شده‌اند. آزمون رندر حذف لینک تکراری و عنوان نمایشی را بررسی کرد.
- `npm run verify`، ESLint، ساخت تصویر تولید وب و هر دو بررسی npm audit موفق بودند. نسخهٔ وب `20261121-cart-toolbar` منتشر شد. صفحهٔ اصلی فارسی و انگلیسی و مسیر سبد از دامنه پاسخ سالم دادند. تصویر API و پیکربندی ایمیل همان نسخهٔ قبلی باقی ماندند.
