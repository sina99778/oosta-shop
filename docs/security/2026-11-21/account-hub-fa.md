# صفحهٔ حساب و یافتن فرم تأیید

- در نسخهٔ قبلی فیلد کد فقط پس از درخواست ارسال در همان تب نشان داده می‌شد. اکنون مشتری احرازهویت‌شده با ایمیل تأییدنشده می‌تواند پس از رفرش یا بازگشت از Gmail کد را در بخش امنیت وارد کند. ایمیل تأیید به همان فرم پیوند دارد و توکن را در URL قرار نمی‌دهد. بازیابی رمز همچنان پیوند مستقل دارد.
- صفحهٔ حساب از DTO موجود `/auth/me` نام نمایشی، ایمیل، شمارهٔ موبایل و شناسهٔ ورود را نمایش می‌دهد و خریدها از مسیر مالک‌محور `/orders` می‌آیند. صفحهٔ عمومی و پاسخ‌های خصوصی روی دامنه با no-store بررسی شدند. پاسخ ناشناس هر دو API برابر ۴۰۱ بود.
- در حساب آزمایشی، Resend تحویل کد تأیید را ثبت کرده بود و چالش در زمان بررسی مصرف نشده بود. خوشامدگویی بعد از تأیید موفق ارسال می‌شود.
- `npm run verify`، ESLint، بیلدهای تولید Docker و هر دو npm audit پاس شدند. چیدمان حساب و پایداری فیلد کد بعد از رفرش در عرض ۳۶۰ و ۱۲۸۰ با مرورگر و دادهٔ ساختگی بررسی شد. نسخهٔ `20261121-account-hub` روی سایت فعال شد. تست Gmail و پرداخت زنده نیازمند اقدام کاربر بودند.
