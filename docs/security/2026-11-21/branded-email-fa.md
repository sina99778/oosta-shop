# قالب ایمیل اوستا

- بازیابی رمز، تأیید ایمیل حساب، تحویل، رسید ردشده، بازپرداخت و یادآوری تمدید همچنان از SMTP و کنترل‌های قبلی استفاده می‌کنند. پیام‌ها دو نسخهٔ HTML و متن ساده دارند. توکن و پیوند یک‌بارمصرف در ایمیل باقی می‌مانند و در صف سفارش ذخیره نمی‌شوند.
- متن پویا برای HTML ایمن‌سازی می‌شود. لینک‌ها در تولید HTTPS هستند. پیام تحویل شامل رمز یا جزئیات محصول نیست. برای ایمیل تأییدنشده، لینک عمومی داشبورد نمایش داده می‌شود و شمارهٔ سفارش در پیام قرار نمی‌گیرد.
- قالب تبلیغاتی آدرس لغو عضویت می‌خواهد. نمونهٔ پیش‌نمایش دادهٔ ساختگی دارد. ارسال کمپین یا مدیریت مخاطبان در این تغییر فعال نشده است.
- ایمیل خوشامدگویی بعد از اولین تأیید نشانی ایمیل و برای هدیهٔ قابل‌استفاده ارسال می‌شود. از همان کد ۱۵ درصدی صندوق پیام استفاده می‌کند. تراکنش تأیید و مصرف کد تأیید جلوی ارسال هم‌زمان و تکراری را می‌گیرد. اگر SMTP در همان تلاش در دسترس نباشد، کد در صندوق پیام قابل مشاهده می‌ماند.
- قید یکتایی دیتابیس و کنترل مالکیت و وضعیت سفارش از استفادهٔ کد حساب دیگر یا مصرف دوباره پس از خرید موفق جلوگیری می‌کنند. این محدودیت به حساب کاربری اعمال می‌شود.
- قرارداد قالب، آزمون‌های بازیابی و تحویل با گیرنده و فرستندهٔ ساختگی، `npm run verify`، ESLint بخش‌های تغییرکرده و ساخت API موفق بودند. هر دو بررسی npm audit صفر مورد گزارش کردند. پیش‌نمایش مرورگر در عرض‌های ۳۶۰ و ۱۲۸۰ پیکسل بررسی شد. رندر داخل برنامه‌های ایمیل و تحویل واقعی این قالب‌ها هنوز بررسی نشده است.

## اصلاحات بازبینی

- جهت و تراز در سلول‌های اصلی و سلول دکمه به‌صراحت تعیین شدند. بدنه از حاشیه‌های فیزیکی چپ و راست استفاده می‌کند. پنج نمونهٔ پیش‌نمایش از رندر قالب به‌روز شدند.
- درخواست احرازهویت‌شدهٔ تأیید ایمیل نشان می‌دهد تلاش ارسال تازه آغاز شده یا خیر. درخواست تکراری چالش موجود را عوض نمی‌کند. رابط برای کد ناقص پیام مشخص دارد و فاصله‌های ناشی از کپی را قبل از ارسال حذف می‌کند. پاسخ عمومی بازیابی همچنان برای آدرس‌های معتبر و نامعتبر یکسان است.
- صفحات پیش‌فرض قوانین از فوتر قابل دسترس‌اند. درج آن‌ها در sitemap به انتشار در CMS وابسته است.
