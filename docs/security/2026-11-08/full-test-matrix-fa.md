# آزمون گستردهٔ تأمین‌کننده، ارز و تحویل — ۸ نوامبر ۲۰۲۶

درخواست کاربر اجرای مستقل همهٔ آزمون‌های قابل انجام بود؛ سقف مجموع خرج واقعی همان ۱ دلار/تتر باقی ماند. تنها برداشت واقعی این کار ۰٫۰۱ دلار برای محصول صریح API-test است. هیچ خرید عادی، پرداخت درگاه، پیام تلگرام یا مصرف مدل پولی در آزمون خودکار انجام نشد.

## بررسی‌های اجراشده

- `npm run verify` با exit0: typecheck، کنترل وابستگی، قراردادهای رابط/ارز/تأمین‌کننده، رگرسیون امنیت، smoke شامل ۱۵۲ بررسی و ۱۷ migration/خرید/تحویل/بازپرداخت/restore در PostgreSQL یک‌بارمصرف. دیتابیس کاری seed/reset نشد.
- `npm run lint` روی کل کد پروژه و وب و `npm run build` برای API و وب با exit0. lint ابتدا JavaScript صادرات تلگرام را هم کد برنامه حساب می‌کرد؛ فقط `ChatExport*/**` از ورودی ESLint کنار گذاشته شد.
- هر دو `npm audit` و `npm audit --omit=dev`: صفر advisory در زمان اجرا؛ JSONهای stock-audit در این پوشه‌اند. یک تلاش ابتدا با خطای زنجیرهٔ گواهی متوقف شد؛ اجرای دوباره با CA سیستم موفق شد و اعتبارسنجی TLS خاموش نشد. وابستگی جدیدی اضافه نشد.
- قرارداد تأمین‌کننده: پاسخ HTTP ناموفق، timeout/JSON نامعتبر/بیش‌ازحد بزرگ، مغایرت محصول/تعداد/مبلغ/مرجع، سفارش لغوشده یا معلق و lookup نامعلوم.
- تطبیق تنوع: همهٔ محورهای ضمانت/دسترسی/تحویل/منطقه/سهمیه/مدت، fingerprint عوض‌شده، snapshot قدیمی یا آینده و انتخاب جایگزین فقط از تنوع دقیقاً یکسان.
- ارز رایگان: چرخاندن کلید نمی‌تواند block یا سهمیه را reset کند؛ JSON دفتر خراب پیش از تماس شبکه خطا می‌دهد. USD و USDT مستقل باقی می‌مانند.
- مرورگر واقعی: ورود پروفایل، سفارش تحویل‌شدهٔ قبلی، نمایش/پنهان‌سازی vault بدون چاپ credential، موبایل ۳۹۰×۸۴۴ بدون overflow افقی، خروج/بازگشت مرورگر و رد رمز اشتباه. تصاویر فقط در وضعیت پنهان ذخیره شدند؛ نشست در پایان خارج شد.

## ایرادهای بازتولید و رفع‌شده

۱. مقدار wallet برابر NaN/Infinity می‌توانست از مقایسهٔ Decimal عبور کند؛ قرارداد ابتدا شکست خورد، سپس اعتبارسنجی finite اضافه شد.

۲. قیمت با بیش از شش رقم اعشار می‌توانست هنگام ذخیرهٔ رزرو گرد شود؛ قرارداد شکست‌خورده و رد precision نامعتبر پیش از خرید اضافه شد.

۳. دو درخواست هم‌زمان با requestKey یکسان گاهی به علت بررسی بیرون قفل، ۲۰۰ و ۴۰۹ می‌گرفتند. آزمون واقعی disposable خطای `QA_ATTEMPT_EXISTS` را به جای ۲۰۰ بازتولید کرد. بررسی تکراری بیرون قفل حذف شد؛ داخل قفل مشترک ابتدا replay، سپس مجوز/بودجه و رزرو بررسی می‌شوند. تست هم‌زمانی اکنون یک POST خارجی و پاسخ معتبر برای تکرار را تأیید می‌کند.

۴. بررسی مستقل نشان داد API خرید عادی فروشنده `max_amount` یا quote قابل قفل ندارد. استعلام ۰٫۴۰ دلار تضمین نمی‌کند برداشت POST همان مقدار بماند؛ رد پاسخ گران‌تر پس از برداشت کافی نیست. بنابراین انتخاب iLovePDF SKU54 اجرا نشد. preflight و send کالای stock هر دو قبل از شبکه با `QA_PRICE_LOCK_UNAVAILABLE` مسدودند؛ تست RED ابتدا نبود ردشدن را نشان داد. lookup فقط‌خواندنی برای بازیابی باز مانده است. هیچ حساب واقعی iLovePDF خریداری یا وارد نشده و فعال‌بودن اشتراک تأیید نشده است.

۵. تلاش مالی SENDING/UNCERTAIN/REVIEW اکنون زیر قفل سراسری، خرج بعدی را حتی با UUID مجوز جدید مسدود می‌کند؛ تست RED ابتدا خرید جدید ۲۰۰ به جای ۴۰۹ داد. بودجهٔ تجمعی تمام مجوزها بررسی می‌شود؛ رگرسیون مرز یک دلار و رد خرید بعدی را بدون خرج واقعی پوشش می‌دهد. تغییر انتخاب در تنظیم جاری، انتخاب ذخیره‌شدهٔ تلاش معلق را در reconciliation تغییر نمی‌دهد.

رگرسیون‌های رد دسترسی، نقش جاری دیتابیس، مالکیت سفارش و cache خصوصی حفظ شدند. پنل و DTO نوع API-test را از محصول واقعی جدا می‌کنند؛ انتخاب stock صرفاً آماده‌سازی غیرفعال است. هیچ پارامتر انتخاب کالا یا تأمین‌کننده از body عمومی خرید QA پذیرفته نمی‌شود. بازبین مستقل پس از اصلاحات، یافتهٔ قابل اقدام دیگری در محدودهٔ بررسی گزارش نکرد.

## حدود نتیجه

این مجموعه تضمین نبود باگ یا امنیت کامل سامانه نیست. خرید عمومی تأمین‌کننده، تسویهٔ واقعی مشتری، refund خارجی، تضمین کیفیت/ضمانت فروشنده و فعال‌سازی حساب واقعی هنوز تأیید و فعال نشده‌اند. برای خرید خودکار عادی، فروشنده باید قفل قیمت یا سقف برداشت قابل اعمال ارائه کند؛ صرفاً استعلام دوباره کافی نیست. اعتبار باقی‌ماندهٔ مجوز کاربر خودکار خرج نمی‌شود.


## انتشار و آزمون دامنهٔ واقعی

نسخهٔ `/opt/oostaAI/releases/20261108-full-tests` فعال است. API و وب در سرور نیز با موفقیت ساخته شدند؛ فقط سرویس‌های Oosta بازسازی شدند. پیش از migration، backup جدید `pre-full-tests-post-purchase-20261108.dump` از دیتابیس دارای خرید واقعی گرفته شد و imageهای قبلی نگهداری شدند. migration انتخاب QA افزودنی است؛ سقف رزرو DB تا یک دلار اجازه می‌دهد ولی خرید stock در هر دو entry point پیش از شبکه مسدود است. هیچ reset/seed یا rollback دفتر خرید رخ نداد. `nginx -t` موفق بود.

آزمون HTTPS عمومی پس از انتشار: ورود پروفایل ۲۰۰، vault صاحب سفارش ۲۰۰ با `private, no-store`، کاربر دیگر ۴۰۴، دسترسی USER به مدیر ۴۰۳، خرید بدون مجوز فعال ۴۰۳. یک تلاش DELIVERED با هزینهٔ ۰٫۰۱ دلار و دقیقاً یک inventory باقی ماند؛ انتخاب legacy به‌صورت API-test نمایش داده شد. دفتر ارز همان ۲ تلاش قبلی را نگه داشت. وضعیت مدیر هر پنج تأمین‌کننده را configured و سود را ۳۰ درصد نشان داد. مقدار هیچ کلید، توکن یا credential تحویل‌شده در خروجی بررسی چاپ نشد.

اسکریپت `preview-http-check.cjs` روی دامنهٔ واقعی با گزینه‌های login-ready و supplier-qa-ready پاس شد: صفحه و فایل ایستا، cache خصوصی، رد نوشتن عمومی و اعتبارسنجی ورود. مجوز QA غیرفعال باقی ماند؛ پرداخت عمومی فعال نشد.
