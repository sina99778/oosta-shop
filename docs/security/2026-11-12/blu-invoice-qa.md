# Blu invoice pilot

Implemented on the working branch. The three BLU_INVOICE settings remain unset on production. The pilot applies only to one configured authenticated user and the configured receiving card. There is no client override. The IBAN and allocation key stay server-side. Existing manual orders remain compatible.

The allocator converts the catalog total to integer rials, serializes reservations for each receiving IBAN, and uses a database unique index over the account and payable amount. Rials and tomans share that key space. It chooses a 1–249 toman discount, so the customer sees an amount at or below the listed price. The saved snapshot contains base price, adjustment, payable rials, account and card, and a 30-minute deadline. It survives card-setting changes and remains reserved after expiry while the order is retained. The public-facing owner response contains the price adjustment and time remaining. Order status is not changed by expiry and a late receipt can still be submitted. The checkout hides payment instructions on deadline or when an expired response arrives and rechecks the server on return to the tab.

The ordinary manual checkout can still have an identical amount on the same card. The uniqueness guarantee covers retained Blu allocations, not all incoming transfers. The bank account is shared with personal use. Do not use amount alone as payment evidence. A store restore can rewind allocations; future live activation requires explicit reconciliation before any automatic confirmation resumes.

An isolated HTTP regression initially failed because concurrent identical orders all returned the same total. The checkout rendering regression initially lacked discount information. After the changes, the regressions cover concurrent allocations, ordinary legacy orders, anonymous/non-owner denial, private no-store policy, cross-currency collisions, changed and invalid destination snapshots, expiry with late receipt upload, and exhaustion without creating an order. An independent code review identified clock skew in a browser wall-clock timer. The server-relative timer and refresh-on-resume address it. No bank event endpoint, transaction claim, order payment, or automatic delivery was run in this phase.
