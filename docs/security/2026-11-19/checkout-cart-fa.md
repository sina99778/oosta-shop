# سبد خرید، فاکتور و پرداخت کارت‌به‌کارت

- افزودن به سبد فقط برای حساب مشتری احرازشده و پلن فعال است. سبد و فاکتور خروجی خصوصی با `Cache-Control: private, no-store` دارند. شناسهٔ ردیف‌های فاکتور و سفارش در سمت سرور با مالک حساب بررسی می‌شوند.
- هر ردیف از زمان افزودن ۲۴ ساعت اعتبار دارد. افزودن دوباره همان ردیف زمان رزرو را تمدید نمی‌کند. رزرو کالای داخلی با قفل ردیف موجودی انجام می‌شود. حذف و انقضا رزرو را آزاد می‌کنند و هنگام تأیید، رزرو در تراکنش به سفارش منتقل می‌شود. پرداخت دارای رسید، ادعای بانکی یا نتیجهٔ نامشخص درگاه تابع مسیر بررسی و تسویهٔ سفارش است.
- کالاهای داخلی با ارز یکسان می‌توانند فاکتور مشترک داشته باشند. در سبد، افزایش حداقل ۱۰۰ هزار تومان و وضعیت عدم موجودی در سطح کالا دیده می‌شود. مبلغ تک‌تک ردیف‌ها در تأیید نهایی بازبینی می‌شود که تغییر جبران‌شده در جمع فاکتور هم از بررسی رد نشود.
- فاکتور هر کالای تأمین‌کننده مستقل است. سبد در فروشگاه ثبت می‌شود و قبل از پرداخت به‌روز بودن قیمت و عرضه دوباره استعلام می‌شود. API تأمین‌کنندگان برای این سبد رزرو ۲۴ ساعته ارائه نمی‌کند. خرید و تأیید رسید تابع سیاست فعلی تأمین و کنترل ادمین است.
- کد تخفیف به شکل `OOSTA_DISCOUNT_CODES=CODE:10,OTHER:15` در متغیر محیطی API تنظیم می‌شود. درصد مجاز از ۱ تا ۹۰ است. قیمت و تخفیف در مرورگر فقط نمایش داده می‌شوند و مبلغ پرداخت دوباره در سرور محاسبه می‌شود. کدها بدون تنظیم اپراتور خالی‌اند. محدودیت مصرف، انقضای اختصاصی و مدیریت از پنل در این نسخه وجود ندارد.
- شمارهٔ پیگیری در فاکتورهای جدید کارت‌به‌کارت و مسیرهای قدیمی که کنترل بانکی می‌خواهند، در فرم و API اجباری است. رقم‌های فارسی و عربی برای مقایسه به لاتین تبدیل می‌شوند. سفارش قدیمی که API آن شمارهٔ پیگیری اختیاری دارد همان رفتار را حفظ می‌کند.

آزمون‌های ایزوله از دادهٔ مصنوعی استفاده می‌کنند و شامل انقضا، رزرو رقابتی، کنترل مالکیت، دستکاری تخفیف، تغییر قیمت با جمع ثابت، فاکتور چندمحصولی، ارسال هم‌زمان پرداخت و تغییر قیمت تأمین‌کننده هستند. این آزمون‌ها هیچ خرید، پرداخت واقعی یا ارسال پیام تلگرام انجام نمی‌دهند.

`npm run verify`، بررسی ESLint فایل‌های تغییرکرده و بیلد API و وب اجرا شدند. هر دو بررسی `npm audit --omit=dev` و `npm audit` با گواهی‌های مورد اعتماد سیستم اجرا شدند و آسیب‌پذیری ثبت‌شده‌ای گزارش نکردند. آزمون‌های بالا رفتار بررسی‌شده را پوشش می‌دهند و جایگزین اعتبارسنجی دوره‌ای سرویس‌های بیرونی نیستند.

در انتشار `20261119-cart-checkout`، مهاجرت روی سرور اعمال شد. صفحات سبد و بازبینی از دامنهٔ عمومی پاسخ گرفتند و عملیات سبد بدون احراز هویت رد شد. با حساب موقت روی سرور، پلن یک‌ماههٔ ChatGPT Plus به سبد رفت، فاکتور کارت‌به‌کارت بازبینی شد و سبد و حساب بدون ایجاد سفارش پاک شدند. پلن‌های تأمین‌کننده که خریدشان از قبل فعال نبوده است، همچنان ممکن است فقط قیمت استعلامی داشته باشند.

در آزمون سرتاسری بعدی، یک سفارش تأمین‌کننده از سبد و فاکتور تا ثبت HTTP رسید، اعلان خصوصی تلگرام، بررسی دسترسی ادمین و تحویل طی شد. شمارهٔ پیگیری خالی رد شد و رقم‌های فارسی شمارهٔ پیگیری در سفارش به لاتین ذخیره شدند. حساب خریدار وضعیت «در انتظار بررسی» و سپس «پرداخت‌شده، در انتظار تأمین» را دید. تأیید هم‌زمان رسید فقط یک بار موفق شد و ارسال هم‌زمان درخواست تأمین یک خرید مصنوعی و یک تحویل ایجاد کرد. فقط مالک سفارش به اطلاعات تحویل دسترسی داشت. تست‌های Blu نیز با رویداد بانکی امضاشدهٔ مصنوعی اجرا شدند. همهٔ داده‌ها در دیتابیس موقت بودند و اعلان و فروشنده از جایگزین آزمایشی استفاده کردند.
## آزمایش پلن ۵۰۰ اعتبار کپ‌کات (PremiKeyBot)

استعلام پلن در محیط زنده موفق بود و تلاش برای دریافت فاکتور قطعی برای پلن با تحویل بررسی‌نشده با `SUPPLIER_PURCHASE_UNSUPPORTED` رد شد. در تست ایزوله، همین شناسه و قیمت ۰٫۴۶ دلار با API شبیه‌سازی‌شده از سبد، فاکتور کارت‌به‌کارت، بررسی رسید و دستور ادمین عبور کرد. قبل از تأیید رسید درخواستی برای خرید ثبت نشد. تکرار ارسال، برداشت شبیه‌سازی‌شدهٔ دوم نساخت و اطلاعات تحویل از پاسخ خصوصی سفارش خوانده شد.

`npm run verify`، ESLint آزمون و بیلد API موفق بودند. تنظیمات سایت زنده تغییر نکردند. خرید قبلی از تلگرام و مشاهدهٔ Pro تیمی و ۵۰۰ اعتبار در CapCut، تحویل نمونهٔ واقعی را تأیید می‌کنند. پاسخ خرید مستقیم API برای همین پلن در محیط زنده هنوز آزمایش نشده است.

در نوبت بعد با مجوز یک خرید و بررسی قیمت و سقف موجودی بلافاصله پیش از ارسال، API زندهٔ PremiKeyBot یک واحد از همین پلن را ثبت و تحویل داد. هزینه و کاهش کیف پول هر دو ۰٫۴۶ دلار بود. این آزمون از API فروشنده روی سرور انجام شد و فاکتور یا پرداخت مشتری ایجاد نکرد. پاسخ واقعی فقط رمزگذاری‌شده نگهداری شد و برای بررسی قالب به‌صورت محلی و بدون چاپ مقادیر باز شد.

پاسخ واقعی، ایمیل و رمز را به شکل `email|password` در فیلد نام کاربری و رمز جدا را خالی فرستاد. آزمون برگشتی پیش از اصلاح وضعیت نامطمئن گرفت و پس از اصلاح تحویل موفق شد. بستهٔ ناقص یا دارای جداکنندهٔ اضافه همچنان نامعتبر است. اجرای مجدد پاسخ واقعی بدون شبکه، تطبیق محصول، مبلغ و جداسازی اطلاعات ورود را تأیید کرد. `npm run verify`، ESLint و بیلد API پاس شدند. هشدار [GHSA-7589-6fvf-x4pw](https://github.com/advisories/GHSA-7589-6fvf-x4pw) در زنجیرهٔ Prisma همچنان باز است.

## سفارش خصوصی با موجودی تأمین‌شده

تنظیم خصوصی `checkout.privateStock` فقط یک پلن داخلی غیرفعال را به یک حساب مشتری مشخص می‌بندد. کاتالوگ عمومی و مسیر قدیمی سفارش همچنان پلن غیرفعال را رد می‌کنند. سبد در افزودن، نمایش، بازبینی و ساخت سفارش، دسترسی فعلی حساب را بررسی می‌کند. پلن آزمایشی فاکتور تک‌کالا و روش کارت‌به‌کارت دارد. موجودی به یک سفارش رزرو می‌شود و اطلاعات ورود فقط پس از ثبت پرداخت تأییدشده در حساب مالک سفارش نمایش داده می‌شود.

در این آزمایش همان واحدی که پیش‌تر از فروشنده گرفته شده بود به کار می‌رود. ساخت فاکتور به فروشنده درخواست خرید تازه ارسال نمی‌کند. رسید واقعی باید از مسیر عادی بررسی شود.

`npm run verify`، ESLint و بیلد API موفق بودند. آزمون ایزوله نبود پلن در کاتالوگ عمومی، رد افزودن با حساب دیگر، رزرو یک واحد، ندادن اطلاعات تحویل قبل از تأیید و تحویل خصوصی بعد از تأیید رسید را پوشش داد. نسخهٔ `20261120-private-capcut-cart` منتشر شد و یک واحد واقعی در سبد حساب آزمایشی با مبلغ ۱٬۰۰۵ تومان رزرو شد. فاکتور بازبینی شد و پرداخت واقعی هنوز انجام نشده است. هشدار وابستگی Prisma همچنان باز است.
