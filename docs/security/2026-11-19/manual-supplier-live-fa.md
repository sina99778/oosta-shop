# آزمون واقعی و فعال‌سازی خرید تأمین‌کننده

- مالک خرید آزمایشی یک‌واحد Microsoft 365 E3 از Vente با حداکثر مواجههٔ ۰٫۶۶ دلار را تأیید کرد. صورتحساب خصوصی ۱٬۷۳۰٬۹۵۰ ریال برای حساب آزمایشی USER ساخته شد. کاربر رسید را از صفحهٔ عمومی بارگذاری کرد.
- مبلغ، کارت مقصد، شمارهٔ پیگیری و بازهٔ اعتبار صورتحساب با تاریخچهٔ واقعی بلو تطبیق داده شدند. از مبدل و اعتبارسنجی موجود برای بررسی فقط‌خواندنی استفاده شد. رویداد بانک به مسیر تأیید خودکار فرستاده نشد.
- پرداخت با حساب مدیر فعلی تأیید شد. وضعیت تأمین پیش از فرمان مدیر `AWAITING_FUNDS` بود. قبل از خرید، هویت محصول، قیمت، اعتبار مجاز و موجودی واقعی دوباره بررسی شدند. فقط یک خرید ارسال شد. برداشت قطعی ۰٫۵۰ دلار بود، رکورد تأمین `DELIVERED` شد و یک قلم تحویل از مسیر حساب مشتری تأیید شد. اطلاعات تحویل چاپ نشد.
- مسیر دستی روی سرور فعال شد و مسیرهای محدود عملیات مدیر روی Nginx باز شدند. نقش مدیر متصل به چت خصوصی تلگرام و فعال بودن تایمرهای بکاپ و Blu بررسی شدند. ارسال ایمیل کماکان غیرفعال است.
- خواندن سفارش پرداخت‌شده از حساب مشتری با `no-store` و رد دسترسی ناشناس به صف مدیر بررسی شد. استعلام عمومی احراز‌شدهٔ Microsoft 365 و ChatGPT Plus یک‌ماههٔ ضمانت‌دار هر دو قیمت قطعی و کارت‌به‌کارت دستی برگرداندند. در این بررسی سفارش یا خرید دیگری انجام نشد.
- در صفحهٔ جزئیات مدیر، با تغییر وضعیت پرداخت پس از تأیید رسید، بخش تأمین دوباره بارگذاری می‌شود تا دکمهٔ «خرید و تحویل» بدون بازخوانی دستی صفحه به‌روز شود.
- verify کامل، ESLint تنظیم‌شدهٔ وب برای فایل تغییرکرده، build محلی وب، ساخت تصویر وب روی سرور و هر دو audit موفق شدند. auditها صفر هشدار دادند. بعد از جابه‌جایی وب، صفحهٔ محصول و صفحهٔ جزئیات پنل از دامنهٔ عمومی پاسخ ۲۰۰ گرفتند. کانتینر API هنگام نصب اصلاح وب بازسازی نشد.

محدودیت: سقف فروشنده قراردادی نیست. قیمت و موجودی بین آخرین استعلام و ثبت خرید می‌توانند تغییر کنند. نتیجهٔ مبهم همچنان برای بررسی نگه داشته می‌شود و دوباره خرید نمی‌شود. موفقیت یک سفارش، تضمین دسترسی دائمی تأمین‌کنندگان نیست.
