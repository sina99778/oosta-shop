# اصلاحات تجربهٔ خرید پس از ممیزی ویترین

- عنوان پلن در سبد مهمان، سبد حساب و فاکتور با همان قالب صفحهٔ محصول نمایش داده می‌شود. عبارت‌های انگلیسی ضمانت از عنوان نمایشی حذف می‌شوند تا متن خام تأمین‌کننده با ضمانت ثبت‌شدهٔ پلن تناقض ایجاد نکند. تاریخ اعتبار سبد و فاکتور یک بار همراه ساعت نمایش داده می‌شود.
- انتخاب سریع، پلن‌های موجود با نام و مشخصات نمایشی یکسان را یک بار نشان می‌دهد. اولویت ثبت‌شده رعایت می‌شود و در اولویت برابر مبلغ کمتر ترجیح دارد. همهٔ گزینه‌ها در فهرست کامل قابل انتخاب‌اند و شناسهٔ پلن، استعلام، مبلغ و منطق فاکتور تغییر نکرده‌اند.
- در صورت وجود شرایط اختصاصی، دستور تکراری ثبت تیکت از زیر آن حذف شده است. راهنمای پیش‌فرض برای پلن‌هایی که متن اختصاصی ندارند روشن‌تر شد. کنتراست برچسب قیمت نوار خرید موبایل و سطح تیترهای صفحات CMS نیز اصلاح شد.
- عبارت عمومی و تکرارشدهٔ «از متن عرضه قابل تأیید نبود» در ۲۰۷ متن بررسی‌شده هنگام نمایش به راهنمای کوتاه فارسی دربارهٔ شرایط حساب، منطقه و دستگاه تبدیل می‌شود. این اصلاح فقط همان عبارت کامل را جایگزین می‌کند و متن اصلی شرایط فعال‌سازی در پنل مدیریت در دسترس است.

## بررسی‌ها

- قراردادهای سبد و فاکتور، عنوان و ضمانت، انتخاب پلن و تیتر CMS اجرا شدند. `npm run verify` با پایگاه دادهٔ موقت، `npm run lint` و `npm run build -w @oosta/web` موفق بودند. هر دو اجرای `npm audit` و `npm audit --omit=dev` صفر مورد گزارش کردند.
- با Edge محلی و API آزمایشی، حذف کارت هم‌نام از انتخاب سریع، در دسترس بودن آن در فهرست کامل، تعامل فیلترها، رنگ محاسبه‌شدهٔ برچسب قیمت در موبایل و نمایش متن جدید در کنار شروط اختصاصی بررسی شد. یک سناریوی جدا نمایش عنوان پاک‌سازی‌شده در سبد مهمان و سبد مشتری، انتقال پس از ورود و نگه داشتن اقلام در حالت سبد پر را تأیید کرد.
- تغییرات در لایهٔ نمایش وب‌اند. مسیرهای سبد و فاکتور، محافظ ورود، کنترل مالکیت سفارش، کش پاسخ خصوصی API، تأیید پرداخت و تحویل تحت همان قراردادهای موجود بررسی شدند. Markdown همچنان لینک‌های ناامن را رد می‌کند. `Track` از قبل `keepalive: true` دارد.
- بررسی مرورگر روی بیلد محلی انجام شد. متن‌های ذخیره‌شدهٔ CMS و سیاست کش Nginx ویرایش نشدند. در این بررسی سفارش، پرداخت یا اعلان واقعی ثبت نشد.
