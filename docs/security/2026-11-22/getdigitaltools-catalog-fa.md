# اتصال کاتالوگ GetDigitalTools

اتصال `getdigitaltools` کاتالوگ ربات @getdigitaltools_bot را از مسیر ثابت HTTPS با `GET /api/products` و هدر `x-api-key` می‌خواند. کلید از فایل خصوصی تأمین‌کننده روی سرور خوانده می‌شود. پاسخ عمومی مشتری، کلید و دادهٔ داخلی کاتالوگ را دریافت نمی‌کند. دادهٔ کاتالوگ در پنل مدیریت از همان مسیر محدود به مدیر نمایش داده می‌شود.

قیمت با ارز اعلام‌شدهٔ فروشنده، موجودی با مقدار عددی و امکان سفارش تک‌واحدی اعتبارسنجی می‌شوند. تحویل تا بررسی قرارداد «تأییدنشده» و ضمانت نامشخص بدون ضمانت است. عرضه‌هایی که جریان تأیید دانشجویی خودکار یا انتقال لینک تأیید را معرفی می‌کنند، مشمول بررسی جداگانه‌اند و مسیر نگاشت عادی آن‌ها را رد می‌کند.

این فروشنده به رجیستری خرید اضافه نشده است. برای خرید واقعی، رفتار تکرار `request_id`، قیمت نهایی و نحوهٔ تحویل باید بررسی شوند. پلن‌ها بعد از تطبیق دقیق مدت، ضمانت، روش تحویل و نوع دسترسی قابل نگاشت‌اند. سیاست Gemini Pro از این مرحله تغییر نمی‌کند.

نسخهٔ API `20261122-getdigitaltools-catalog` منتشر شد. اولین کاتالوگ ذخیره‌شده ۱۷۴ قلم، شامل ۱۴۱ قلم با موجودی مثبت، داشت. یک عرضهٔ دارای جریان حساس برای بررسی جداگانه علامت خورد. دسترسی بدون نشست به پنل تأمین‌کننده پاسخ ۴۰۱ داد. رجیستری خرید برای این فروشنده آداپتور نداشت و هیچ سفارشی ثبت نشد. وب و پایگاه داده سالم بودند و انتشار به مهاجرت نیاز نداشت.

`npm run verify`، ESLint، بیلد تولید API و دو بررسی npm audit پاس شدند. مجوز خواندن فایل کلید به root و UID 1000 محدود است. پس از پاک‌سازی کش بیلد، ۲٫۴ گیگابایت فضای آزاد و ایمیج API قبلی برای بازگشت حفظ شدند.
