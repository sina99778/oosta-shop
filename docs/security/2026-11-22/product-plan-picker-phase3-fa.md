# مرحلهٔ سوم، بخش ۳ — انتخاب پلن

محصول چندپلنی تا چهار میان‌بر برای پلن‌های موجود نشان می‌دهد. پلن‌های موجود اول می‌آیند و در هر گروه `sortOrder` نزولی است. در تساوی، موجودی فروشگاه بر موجودی تأمین‌کننده مقدم است. انتخاب از کارت سریع و فهرست کامل به همان شناسهٔ پلن می‌رسد. اگر فیلتر فعلی آن پلن را پنهان کرده باشد، انتخاب سریع فیلتر را پاک می‌کند. صفحه‌ای که با شناسهٔ پلن مشخص باز شده همان انتخاب را حفظ می‌کند.

کارت سریع مدت، نوع دسترسی، ضمانت و قیمت را با دادهٔ همان پلن نشان می‌دهد. قیمت ثابت و تخفیف پلن محلی از دادهٔ عمومی محصول می‌آید. فهرست کامل و کارت سریع برای تأمین‌کننده از `IndicativePriceLabel` استفاده می‌کنند. رقم منقضی حذف می‌شود و «قیمت با استعلام» ظاهر می‌شود. قیمت تقریبی به فاکتور یا پرداخت ارسال نمی‌شود. جست‌وجوی زندهٔ تأمین‌کننده هنگام رندر، تغییر دادهٔ ساختاریافتهٔ سئو، تغییر API و مهاجرت پایگاه داده در این مرحله وجود ندارد.

قراردادهای رابط، سقف چهار گزینه، ترتیب، انتخاب فعلی، حالت تک‌پلن و ناموجود، و قیمت معتبر و منقضی را پوشش می‌دهند.

در Edge با دادهٔ ساختگی و نمای ۳۹۰ و ۱۳۶۶ پیکسل، ترتیب کارت‌ها، بازشدن فهرست، فیلتر مدت و همگام بودن انتخاب‌ها بررسی شدند. اولین اجرای مرورگر نشان داد با پاک‌شدن انتخاب حین فیلتر، تغییر محل رندر باعث بازنشانی فهرست می‌شود. پس از ثابت‌کردن محل انتخاب‌گر، فیلتر حفظ شد و انتخاب سریع فقط فیلتر ناسازگار را پاک کرد.

نسخهٔ وب `20261122-product-plan-picker-phase3` منتشر شد. HTML فارسی و انگلیسی، همگام بودن کارت انتخاب‌شده با رادیوی فهرست و قیمت تقریبی در صفحهٔ زندهٔ ChatGPT تأیید شدند. Edge در عرض‌های ۳۹۰ و ۱۳۶۶ پیکسل اسکرول افقی ثبت نکرد. یک خرید واقعی انجام نشد. کانتینر API تعویض نشد و بررسی سلامت دیتابیس موفق بود.

`npm run verify`، ESLint و بیلد تولید وب با موفقیت اجرا شدند و هر دو npm audit صفر مورد گزارش کردند. چهار فایل وب با نسخهٔ منتشرشده تطابق داشتند. پس از جمع‌آوری کش موقت بیلد، ۲٫۵ گیگابایت فضای آزاد باقی ماند و تصویر وب قبلی برای بازگشت حفظ شد.
