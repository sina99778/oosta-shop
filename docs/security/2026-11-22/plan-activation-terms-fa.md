# شرایط و ضوابط اختصاصی فعال‌سازی هر پلن (`ProductPlan.activationTerms`)

برای نمایش شرایط و ضوابط واقعی هر پلن (گرفته‌شده از قوانین ربات‌های فروشنده پس از بازنویسی فارسی و حذف شناسه‌های بیرونی)، فیلد اختیاری `activationTerms` به مدل `ProductPlan` اضافه شد:

### ساختار پایگاه‌داده و API
- **مهاجرت افزایشی** — فایل `apps/api/prisma/migrations/20261122000100_plan_activation_terms/migration.sql` ستون `activationTerms TEXT` را با محدودیت `CHECK ("activationTerms" IS NULL OR char_length("activationTerms") <= 4000)` روی جدول `product_plans` اضافه می‌کند (بدون تغییر یا حذف داده‌های موجود).
- **اعتبارسنجی و سرویس ادمین** — در `admin.schemas.ts` (`createPlanSchema` و `updatePlanSchema`) متن ورودی trim شده، سقف ۴۰۰۰ نویسه دارد و رشتهٔ خالی به `null` تبدیل می‌شود. در `admin.service.ts` به‌روزرسانی `activationTerms` جزء تغییرات معنایی (`semanticChange`) محسوب نمی‌شود تا ویرایش متن راهنما روی پلن‌هایی که موجودی یا سفارش ثبت‌شده دارند با خطای `PLAN_IN_USE` متوقف نشود (همچنین در `cartSignature` دخالت داده نشد تا سبدهای باز منقضی نشوند).
- **کاتالوگ عمومی** — در `catalog.service.ts` (`getProductBySlug`) فیلد `activationTerms` روی پلن‌های صفحهٔ محصول ارسال می‌شود و فهرست‌های جمع‌وجور کاتالوگ/سبد مهمان بدون فیلد اضافه سبک نگه داشته شدند.

### رابط کاربری و پنل ادمین
- **صفحهٔ محصول** — در `apps/web/components/product-detail-view.tsx` بخش تاشو (`<details key={\`terms:\${plan.id}\`}>`) با حفظ حالت بستهٔ اولیه و بدون تداخل با کلید دکمهٔ خرید، وقتی `plan.activationTerms` مقدار داشته باشد با عنوان «شرایط و ضوابط فعال‌سازی این پلن» و رندر امن `Markdown` (مسدودکنندهٔ لینک‌های غیرایمن) نمایش داده می‌شود.
- **پنل ادمین** — در `apps/web/components/admin/plan-row.tsx` امکان ثبت و ویرایش چندخطی `activationTerms` (سقف ۴۰۰۰ نویسه) برای هر پلن اضافه شد.

### اسکریپت‌های استخراج و ورود امن داده‌های ربات فروشنده
- **استخراج فقط‌خواندنی (`scripts/export-supplier-plan-terms.cjs`)** — محصولات و پلن‌های فعال را به‌همراه توضیح و عنوان آفرهای متصل از `site_settings` (`suppliers.catalog.*`) استخراج می‌کند، بدون ذخیره یا چاپ کلیدهای API، هزینه یا موجودی کیف پول.
- **ورود کنترل‌شده (`scripts/apply-plan-activation-terms.cjs`)** — اجرای بدون `--apply` پیش‌نمایش است. با `--apply` به‌صورت تراکنشی اعمال می‌شود و ورودی هر پلن را پیش از نوشتن با `validateActivationTerms` کنترل می‌کند:
  - رد هر آیدی `@handle` غیر از `@oostaAiSupport`
  - رد هر نشانی `http://`، `https://`، `t.me/` یا `telegram.me/` غیر از `https://t.me/oostaAiSupport` و `https://oostaai.store`
  - رد عبارت‌های انگلیسی درخواست رمز عبور (`send ... password/pass`) و متن بالای ۴۰۰۰ نویسه

### بررسی‌ها و حدود فعلی
- `npm run verify` (شامل اجرای ۳۴ مهاجرت روی دیتابیس موقت، تست‌های رگرسیون `product-content-regressions.ts` برای API ادمین/کاتالوگ و اسکریپت‌های export/apply، و قراردادهای `variant-ui-contracts.cjs`)، `npm run lint` و `npm run build` برای هر دو سرویس API و وب پس از آخرین ویرایش با موفقیت کامل اجرا شدند.
- مهاجرت افزایشی اجرا شد و نسخهٔ `20261122-plan-activation-terms` با ترتیب API و سپس Web روی سرور فعال شد. هر دو بیلد تولید، بررسی کامل، lint و هر دو npm audit موفق بودند.
- ۴۱۰ متن فارسی برای تمام پلن‌های فعال ۱۰۱ محصول وارد شد. برای ۲۹۸ پلن عرضهٔ با اثرانگشت منطبق پیدا شد که ۲۷۳ عرضه توضیح داشتند. متن فارسی ۴۹ پلن شرط اختصاصی قابل‌انتشار یا توضیح تأییدشده داشت. بقیه بر اساس مشخصات ثبت‌شدهٔ همان پلن نوشته شدند و محدودیت دادهٔ عرضه در صفحه درج شد. ۱۹ مورد حساس یا ناسازگار برای بررسی از راه پشتیبانی مشخص شدند. متن خام، لینک فروشنده و اطلاعات ورود منتشر نشد.
- شمارش پس از ورود، ۴۱۰ پلن دارای متن را تأیید کرد. API و صفحهٔ عمومی شش محصول بررسی شدند. در Edge با عرض ۳۹۰ و ۱۳۶۶، باز و بسته‌شدن شرایط و تعویض متن با تغییر پلن تأیید شد. سفارش و پرداخت در این بررسی ایجاد نشدند. پس از پاک‌سازی کش بیلد، ۱٫۶ گیگابایت فضای آزاد باقی ماند.
