# مرحلهٔ سوم (بخش ۱): اندازه‌گیری سبد تا پرداخت و پیام‌های قابل‌اقدام فاکتور

برای سنجش دقیق مسیر از بازبینی فاکتور تا شروع پرداخت، دو شمارندهٔ سمت سرور `cart_invoice_reviewed` و `cart_payment_started` در جدول `storefront_step_counts` اضافه شدند. گام‌های قدیمی‌تر کلاینت (`storefrontSteps`) دست‌نخورده ماندند تا مسیر عمومی `POST /track` همچنان ثبت جعلی مراحل پرداخت را رد کند.

- **بازبینی فاکتور (`cart_invoice_reviewed`)** — فقط پس از پاسخ موفق `POST /cart/items/:id/review` ثبت می‌شود. خطاهای ناموجودی، تغییر قیمت یا کد تخفیف نامعتبر شمارش نمی‌شوند و هر بازبینی موفق یک رویداد است (نه شمارش خریدار یکتا).
- **شروع پرداخت (`cart_payment_started`)** — در `POST /cart/items/:id/pay` فقط درخواست موفقی شمارش می‌شود که تراکنش آن سفارش جدید را ایجاد کرده است. این تصمیم در مسیر موجودی داخلی و تأمین‌کننده از نتیجهٔ تراکنش می‌آید و ساختار پاسخ HTTP همان است. در رگرسیون پنج درخواست هم‌زمان، قبل از اصلاح یک سفارش پنج بار شمارش شد. بعد از اصلاح همان سفارش یک بار شمارش شد.
- **گزارش تلگرام** — تابع `visitsMessage` در ربات از `funnelStepLabels` استفاده می‌کند تا «بازبینی موفق فاکتور» و «شروع موفق پرداخت» در کنار مراحل قبلی با برچسب فارسی نمایش داده شوند.

در صفحهٔ تأیید و سبد خرید (`shopping-cart.tsx` و `apps/web/lib/cart-review.ts`) تجربهٔ خطا و انقضا اصلاح شد:

- **اعتبار فاکتور** — زمان اعتبار (`invoice.expiresAt`) پیش از دکمه‌های پرداخت نمایش داده می‌شود و با پایان مهلت (از طریق تایمر سمت کلاینت و بررسی پیش از ارسال در `pay()`) دکمه‌های پرداخت غیرفعال شده و دکمهٔ «دریافت فاکتور تازه» نمایش داده می‌شود.
- **پیام‌های قابل‌اقدام** — در خطای تغییر قیمت یا انقضای استعلام تأمین‌کننده (`CART_CHANGED`، `SUPPLIER_QUOTE_EXPIRED`، `INVOICE_EXPIRED`) دکمهٔ «دریافت فاکتور تازه»، در خطای ناموجودی یا نبودن کالا در سبد (`OUT_OF_STOCK`، `NOT_FOUND`) لینک «بازگشت به سبد خرید» و «انتخاب پلن دیگر» (هم در خط ناموجود سبد و هم در صفحهٔ تأیید)، و در خطای سفارش باز (`BLU_STOCK_ORDER_OPEN`، `WELCOME_GIFT_PENDING`) لینک «مشاهدهٔ سفارش‌ها» به بخش `dashboard#account-orders` نمایش داده می‌شود.

تست‌های رگرسیون و قرارداد (`storefront-metrics-regressions.ts`، `cart-regressions.ts`، `scripts/cart-review-contracts.cjs`) رد کردن ورودی جعلی `/track`، وجود برچسب‌های فارسی، شمارش بازبینی تکراری، عدم شمارش درخواست ناموفق و تلاش تکراری `/pay` و نگاشت زمان انقضا و خطاها را پوشش می‌دهند. `npm run verify` (شامل دیتابیس موقت و ۱۸۲ بررسی پایه)، `npm run lint` و `npm run build` برای هر دو سرویس API و وب با موفقیت اجرا شدند.

نسخهٔ `20261122-cart-to-payment-phase3` روی سرور فعال است. API قبل از وب منتشر شد. سلامت پایگاه داده، پاسخ ۴۰۱ برای بازبینی و پرداخت بدون نشست و بازشدن صفحهٔ سبد بررسی شدند. شش فایل کلیدی با نسخهٔ محلی تطبیق داشتند. مهاجرت جدیدی وجود نداشت. پس از پاک‌سازی کش موقت بیلد، ۲٫۸ گیگابایت فضای آزاد باقی ماند و تصاویر نسخهٔ بازگشت حفظ شدند.

در Edge با نمای ۳۹۰ پیکسلی و API ساختگی، پایان اعتبار فاکتور، فعال شدن پرداخت پس از دریافت فاکتور تازه، لینک سفارش باز و راه انتخاب پلن دیگر بررسی شدند. قالب گزارش تلگرام در کانتینر منتشرشده با دریافت‌کنندهٔ ساختگی و خواندن آمار بررسی شد. پیام واقعی تلگرام و تراکنش واقعی در این مرحله انجام نشدند. هر دو بررسی npm audit صفر مورد گزارش کردند.
