# فضای دیسک و چرخش لاگ‌های اوستا

- فضای آزاد پارتیشن ریشه از ۱٫۵ به ۲٫۳ گیگابایت رسید. ۱۳ ایمیج قدیمی وب پس از بررسی نبود کانتینر وابسته و وجود سورس ساخت حذف شدند. ایمیج فعال و ایمیج بازگشت `20261122-policies-and-ga4` در دسترس‌اند. فایل swap حدود ۲ گیگابایتی فعال است و در بررسی حدود ۱٫۴ گیگابایت آن در استفاده بود. لاگ‌های میزبان، بکاپ‌ها و حجم‌های داده در پاک‌سازی دست‌نخورده ماندند.
- `journald` سقف ۱ گیگابایت، حداقل فضای آزاد هدف ۲ گیگابایت و نگهداری حداکثر ۱۴ روز داشت. تایمر Nginx فعال بود و چرخش روزانه و نگهداری ۱۴ فایل بررسی شد. دو کانتینر بیرون از Compose اوستا حدود ۱۳۷ و ۵۸ مگابایت لاگ `json-file` بدون سقف داشتند.
- `docker-compose.prod.yml` برای سرویس‌های اوستا سقف ۱۰ مگابایت برای هر فایل و پنج فایل برای هر کانتینر تعریف می‌کند. مقایسهٔ خروجی نهایی Compose با پروفایل پراکسی نشان داد تنها تنظیم لاگ تغییر کرده است. تنظیم در نسخهٔ فعال سرور نصب شد و پس از بازسازی فقط کانتینر وب با همان ایمیج، با `docker inspect` تأیید شد. برای API و PostgreSQL هنگام بازسازی برنامه‌ریزی‌شدهٔ کانتینر اعمال می‌شود. پراکسی میزبان از چرخش موجود خودش استفاده می‌کند.
- صفحهٔ اصلی و اتصال API به دیتابیس پس از کار سالم پاسخ دادند. شناسهٔ کانتینرهای API و PostgreSQL پیش و پس از عملیات یکسان بود. تغییر ایمیج یا بیلد جدیدی لازم نبود. `npm run verify` و `npm run lint` نیز موفق بودند.
- بررسی جانبی نشان داد `sitemap.xml` با `200` و ۱۱۹ آدرس یکتا پاسخ می‌دهد و در `robots.txt` معرفی شده است. طبق گزارش ۱۸ نوامبر، آخرین وضعیت مشاهده‌شدهٔ Sitemap در Search Console برابر `Success` بود. گزارش فعلی پنل دوباره خوانده نشد و سه صفحهٔ قوانین همچنان `noindex` دارند.
