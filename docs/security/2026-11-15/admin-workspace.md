# Admin workspace refresh

The localized admin entry route now shows a sales and payment overview. Product listing moved to `/[locale]/admin/products`. Product creation and detail back links point to that listing. `/[locale]/admin/dashboard` remains available. The grouped desktop sidebar and mobile menu use the same route definitions, current-page markers and admin session guard. The authenticated workspace has a dedicated storefront link and sign-out action.

The dashboard consumes the existing `/admin/stats` and `/admin/blu/status` responses. It links into existing receipt, order and product pages. The chart covers seven UTC calendar dates, including the ongoing day. Review identified that an older date in the API's rolling data can be partial, so the view and its scale exclude it. Missing dates render as zero. The accessible details table exposes chart values. The low-stock group is labeled internal inventory because its existing source does not represent supplier availability. The dashboard renders customer names without contact details. The existing admin DTO still includes emails and phone numbers. The payment indicator counts orders awaiting review. The receipt queue can include multiple receipts for one order. Existing totals include recorded test orders. The dashboard has loading and retry states.

No backend authorization, receipt validation, payment logic, inventory transition or public cache rule changed. The localized layout still requires `ADMIN` and the API independently requires a current database admin role. `/admin` API responses remain private/no-store. Order and receipt page changes are limited to headings, responsive layout and accessible filter selection. The synthetic render contract checks RTL/English output, navigation, contact privacy, payment and stock links, chart day count, loading and failures. This contract doesn't measure rendered layout.

Full verify, ESLint, the render contract, both dependency audits and the production web image build passed. Both audits returned zero advisories. Release `20261115-admin-workspace` updated only the web container. Both locales, the legacy dashboard route, products, receipts, orders and storefront returned 200 through origin HTTPS. The existing Blu timer stayed active. Live GET requests to stats and Blu status returned 401 without authentication, 403 for a regular user and for a stale admin token on that user, and 200 for a current admin. All had private/no-store. The local preview server launch was rejected by automatic review with `blocked by policy`. Authenticated browser rendering on mobile and desktop was not independently observed.

## Second pass

Payment review links and Blu state occupy the first operational row. Dashboard sales and order lists share a consistent currency and status presentation with the Orders route. The dedicated receipt page shows the source evidence, receipt metadata and review controls in reading order. Approval stays disabled while Blu is waiting or reporting a conflict, and now also for paid, refunded or expired orders. This is a UI guard in addition to the existing server checks. The existing receipt image access and write endpoints did not change. Object URLs are revoked when hidden or unmounted. The product search filters the already authorized response locally by name, slug and category. Product counts are labeled inventory records because the existing total includes sold and reserved units.

The synthetic render contract covers both locales, overview data, private contact display, the default receipt queue, waiting/conflicting/matched evidence, closed-order approval denial and product list controls. It reproduces the empty last-page bug in orders and receipts. The UI offers a first-page fallback and moves one page back after review of the last pending receipt on a page. The dashboard, orders, receipts and products rendered in offline Edge with synthetic data at 1440, 390 and 320 pixels without horizontal document overflow. This does not exercise a real logged-in browser session.

Full verify, ESLint, the render contract, dependency audits and the production web image build passed. Both audits reported zero advisories. Release `20261115-admin-polish2` updated only the web container. The four admin pages in both locales and the storefront returned 200 over origin HTTPS. Unauthenticated requests to all four relevant admin APIs returned 401. The Blu timer remained active.
