# Product inventory workspace

The product list and detail APIs add inventory summaries under the existing current-admin guard and private/no-store cache policy. Internal stock is aggregated in SQL by plan and state. The list separates available units on active plans from available units on inactive plans and counts reserved and sold internal units separately. Products with no active internal plan are excluded from the dashboard's internal low-stock queue. Null-plan historical entries remain in the legacy inventory record total and are excluded from categorized counts. Existing list/detail fields remain available.

Supplier availability in product detail uses the same cached, current, variant-matched offers as the storefront. Internal and supplier quantities are never added together. The supplier count is the largest matched offer, not a total across accounts. Manual on-request offers have their own state; absence of a fresh matching offer reads as unconfirmed. These reads do not sync sellers or initiate a purchase.

The product UI filters by low/empty internal stock, active supplier plans and inactive products. The product editor has direct navigation to plans and stock import. Bulk import only offers internal plans, selects a sole eligible plan and keeps the existing server validation, authorization and plan lock. Overview and detail return count data without new credential fields. No payment, customer ownership or delivery logic changed.

The disposable regression first reproduced missing stock counts, then asserted available, reserved, sold and inactive counts, current-role denial, no-store and no credential disclosure. Synthetic supplier cases cover fresh confirmed stock and missing coverage. The component contract and offline visual fixture cover product filters and rendering at 320, 390 and 1440 pixels. The fixture uses synthetic server data.

Independent review found a pre-existing race when deleting a plan during import. The disposable test held the plan row lock and inserted an uncommitted unit. The old deletion queued, then removed the plan after the insert committed. Deletion now locks the same row before checking inventory and orders, so it returns conflict after the committed import and leaves the item attached. The browser also retains the effective selected plan when an import draft starts. If that plan later disappears or changes source, submission requires selecting a valid internal plan. The delete and import request schemas and response codes are preserved.

Full verify, ESLint, the product render contract, production API/web image builds and both dependency audits passed. Release `20261115-admin-inventory` served both locales and the public admin route over HTTPS. Live private product API checks returned 401 for anonymous, 403 for an ordinary user with a stale admin claim, and 200 with no-store for a current admin. All 101 live inventory summaries had nonnegative integer counts. A live product detail exposed no inventory credentials. The Blu timer remained active and Telegram started without a launch error. No production inventory write was used for verification.
