# Storefront mobile loading

The homepage product grid renders on the server. Its category links and native sort form open the full catalog with the existing query parameters. Product cards use low-priority image loading. Header, footer, homepage shortcuts and catalog links fetch destinations on click. The released Estedad WOFF2 is 91,180 bytes (previously 128,304). It keeps the original 100–900 axis, Arabic shaping tables, and license metadata. Removed decorative Geist font uses on the homepage. The 320px hero WebP is 27,584 bytes (previously 41,316). Its original 640px variant remains in the same responsive image.

The public catalog normalizes the category slug and allowlists the sort key before sending them to the API. The API validates its own query and returns the same public product DTO. The Nginx asset allowlist adds only the new versioned WebP. The database, payment, supplier, role and private cache configurations were outside the change. The homepage contract was observed failing on the previous implementation and passing after the change.

`npm run verify` passed, including the isolated database run and 166 smoke checks. In the initial run the signed-event regression suite logged one expired transaction and completed successfully. `npm run lint`, `npm run build`, and the VPS production web image build passed. Both npm audits reported zero advisories when rerun with the Windows system trust store. No production order, real payment or Telegram notification was sent by the tests.

Production checks covered the Persian and English homepages, sorted catalog, ChatGPT details, and unauthenticated admin, order and ticket requests returning 401 with private cache headers. Public checkout remained in preview mode. The final browser font was checked against the source artifact by SHA-256.

For some pre-release chunk URLs, Arvan returned both the correct one-year immutable header and a private/no-store header on a cache HIT. The direct origin and a fresh CDN cache key for the same asset returned the correct immutable header alone. After the mobile hero deployment, GET checks of all 13 referenced script and stylesheet URLs returned no private/no-store header. Previously cached URLs may need a targeted CDN-panel purge if the issue reappears.

Browser observations use a 390×844 viewport, device scale 2, 3× CPU slowdown, 120 ms network latency and 200,000 bytes/sec download throughput. The analytics endpoint was blocked. Before the changes, the Persian homepage loaded 180,700 bytes of fonts and 167,358 bytes of images. The mobile hero release loaded 91,180 bytes of fonts and 153,626 bytes of images. Font traffic fell by 49.5%. Homepage LCP varied from 1.096 to 2.864 seconds across the measured runs. The variable network/render times do not support a consistent percentage LCP speedup claim.

The final navigation release measured zero automatic RSC page-prefetch requests on the homepage, previously 10. Its three cold-cache homepage LCP observations were 1.600, 1.112 and 1.128 seconds. These are simulated mobile measurements from the development machine against the public domain, not real-user field data from Iran. Sorting on the homepage now opens the full catalog, preserving its query-driven validation.
