# بررسی محلی فروشگاه اوستا در ۱۸ نوامبر ۲۰۲۶

## یافته‌ها به‌ترتیب اولویت

1. **قیمت شروع محصول با ترکیب ریال و تومان اشتباه می‌شود.** پنل مدیریت هر دو واحد را برای پلن می‌پذیرد. در تست حافظه‌ای با توابع واقعی `toSummary` و `formatPrice`، دو پلن داخلی ۱۰۰٬۰۰۰ ریالی و ۹٬۰۰۰ تومانی به کارت «۹۰۰ تومان» دادند. تابع عدد خام کوچک‌تر را برمی‌گزیند و واحد پلن اول را کنار آن می‌گذارد. مرتب‌سازی بین محصولات و خلاصهٔ جزئیات نیز عدد خام را مقایسه می‌کنند. پیشنهاد می‌شود مبلغ مؤثر و مبلغ پیش از تخفیف به یک واحد مشترک تبدیل شوند و مقایسه و نمایش از همان داده استفاده کنند. برای هر دو ترتیب پلن و مرتب‌سازی بین دو محصول تست لازم است. شواهد در `apps/api/src/modules/catalog/catalog.service.ts`، `apps/web/components/product-card.tsx` و `apps/web/lib/format.ts` است. این بررسی خطای نمایش را نشان داد. مبلغ برداشت واقعی بررسی نشد.
2. **ممیزی کامل npm برای زنجیرهٔ ابزار توسعه ۱۴ مورد با شدت بالا ثبت کرد.** ریشهٔ گزارش picomatch و شناسهٔ GHSA-fc5q-39xc-vjpf است. خروجی ممیزی با حذف وابستگی‌های توسعه صفر بود. پیشنهاد خودکار اجباری npm شامل بازگشت eslint-config-next به 14.2.35 است. اصلاح سازگار با Next پروژه باید جداگانه با lint، build و هر دو ممیزی تأیید شود.
3. **قطعی API برای مقاله و صفحهٔ محتوایی به صفحهٔ پیدا نشد می‌رسد.** در بازبینی مسیرهای blog و p، فراخوانی اختیاری fetchJson خطای ۵۰۰ و پایان مهلت را به null تبدیل می‌کند و صفحه notFound را فرا می‌خواند. جزئیات محصول از قبل حالت required دارد که خطای موقت را جدا می‌کند. همان رفتار را روی دو مسیر محتوا اعمال کنید و پاسخ‌های ۴۰۴ و ۵۰۰ را جداگانه تست کنید. همچنین sitemap با خطای یک درخواست، ورودی‌های همان بخش را حذف و نتیجهٔ ناقص برمی‌گرداند. بهتر است ساخت ناموفق از نقشهٔ خالی یا ناقص قابل تشخیص باشد.
4. **نمایش جزئیات سفارش فایل‌های رسید را از دیتابیس می‌خواند.** در `orders.service.ts`، تابع getOrderDetail تمام ستون‌های رسید و محصول را می‌گیرد. پاسخ فقط فرادادهٔ رسید را برمی‌گرداند. اندازهٔ دادهٔ خوانده‌شده با تعداد و حجم پیوست‌ها رشد می‌کند. ستون‌های لازم برای پاسخ را با select مشخص کنید و برای این مسیر بایت‌های تصویر را نخوانید.
5. **هزینهٔ برخی فهرست‌ها با کل مجموعه رشد می‌کند.** کاتالوگ برای ترتیب قیمت و موجودی، همهٔ محصولات مطابق فیلتر و پلن‌های فعالشان را پیش از برش صفحه می‌خواند. پنل مشتری هنگام باز کردن یا پاسخ دادن به یک تیکت نیز کل مکالمه را می‌گیرد. برای کاتالوگ، محاسبهٔ ترتیب و اعمال محدودیت صفحه را به دیتابیس منتقل کنید. برای مکالمه، پیام‌های قدیمی را صفحه‌بندی کنید. زمان پاسخ زیر بار اندازه‌گیری نشد.

## شواهد اجرا

- npm run verify با کد صفر تمام شد. مجموعهٔ ایزوله مهاجرت، تحویل همزمان، منع دسترسی به سفارش دیگری، ابطال نشست، تأیید پرداخت، بازپرداخت و بازیابی نسخهٔ پشتیبان را با داده‌های آزمایشی بررسی کرد. پایگاه‌دادهٔ موقت در پایان حذف شد.
- npm run lint و npm run build هر دو با کد صفر تمام شدند. بیلد وب ۵۲ صفحهٔ استاتیک را تولید کرد.
- npm audit --omit=dev صفر مورد و npm audit کامل ۱۴ مورد بالا گزارش داد. بعد از خطای اولیهٔ زنجیرهٔ گواهی، هر دو با گواهی‌های مورد اعتماد سیستم تکرار شدند.
- در Chrome با کاتالوگ نمونه، خانه، جست‌وجو، جزئیات محصول، ورود و ثبت‌نام فارسی در عرض ۳۹۰ و خانه و کاتالوگ انگلیسی در عرض ۱۴۴۰ پیکسل بررسی شدند. جهت متن درست بود و عرض سند از عرض نمایشگر فراتر نرفت. جست‌وجوی Claude فقط لینک همان محصول را برگرداند.
- در کد، بررسی نقش فعلی و نسخهٔ نشست از دیتابیس، شرط مالکیت سفارش و تیکت، هدر کش پاسخ خصوصی و اعتبارسنجی ورودی مسیرهای خرید و رسید بررسی شد.

دامنهٔ بررسی شامل مخزن فعلی، مرورگر محلی و سرویس‌های آزمایشی بود. استقرار عمومی، پرداخت بانکی واقعی، دسترس‌پذیری با صفحه‌خوان و تست بار تولیدی ارزیابی نشدند. تنها تغییر این بررسی ثبت گزارش است.
