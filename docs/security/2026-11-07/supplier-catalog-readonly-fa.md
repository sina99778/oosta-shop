# خواندن کاتالوگ‌های واقعی — ۷ نوامبر ۲۰۲۶

کاربر کلیدهای پنج اتصال را در فایل خصوصی خارج از repo وارد و درخواست بررسی کاتالوگ را تأیید کرد. هویت Canboso اول طبق اعلام کاربر `shop_cron191_en_bot` با CANBOSO_API_KEY و دومی `PremiKeyBot` با CANBOSO2_API_KEY است. این نام‌گذاری از اطلاعات کاربر آمده است؛ نام ربات از endpoint محصولات اثبات نمی‌شود. دو مقدار کلید متفاوت‌اند و کاتالوگ‌های متفاوت دریافت شد.

## دامنهٔ درخواست‌ها

فقط یک GET احرازشدهٔ products برای هر اتصال ارسال شد؛ به ToolsMarket، AItoolify، دو حساب Canboso و VenteBot. همه HTTP 200 و JSON کاتالوگ برگرداندند. هیچ POST، خرید، رزرو، شارژ، فعال‌سازی، پیام تلگرام، درخواست مدل، پرداخت یا تغییر تنظیمات انجام نشد. مقدار balance هم خوانده نشد. برنامه و DB کاری/منتشرشده تغییر نکردند.

| اتصال | ردیف کاتالوگ | عنوان نامزد چهار خانواده |
|---|---:|---:|
| ToolsMarket | 64 | 16 |
| AItoolify | 51 | 11 |
| Canboso اول | 80 | 25 |
| Canboso دوم | 463 | 52 |
| VenteBot | 91 | 9 |
| مجموع | 749 | 113 |

تعدادها snapshot همین دریافت‌اند؛ محصولات یکتا یا آمادهٔ فروش نیستند. تشخیص عنوان با کلیدواژه صرفاً استخراج نامزد است، نه نگاشت نهایی. همهٔ ۱۱۳ ردیف هنوز UNREVIEWED هستند. دو Canboso در این snapshot ده نام کاملاً یکسان ولی هیچ productId مشترک نداشتند؛ تشابه نام دلیل هم‌ارزی نیست.

## یافته‌های مؤثر بر طراحی

- بین نامزدها Trial/آفر، اجارهٔ OTP و اعتبار API Gemini دیده شد؛ این‌ها نباید به‌عنوان اشتراک کامل برنامه با محصول مشتری مقایسه شوند. پنج ردیف اعتبار API Gemini جدا علامت خوردند.
- سه عنوان در متن خود ضمانت کامل داشتند ولی توضیح همان محصول عبارت متناقض «بدون ضمانت» داشت. این پرچم نیاز به بررسی فروشنده دارد و اعتبار ضمانت را تأیید یا رد قطعی نمی‌کند. اختلاف قیمت چنین مواردی معیار خرید خودکار نیست.
- یک مورد AItoolify در عنوان فعال‌سازی روی ایمیل مشتری داشت، درحالی‌که requires_email=false بود؛ توضیح محصول ارسال ایمیل و رمز به پشتیبانی را می‌خواست. این مورد برای MVP تحویل خودکار بدون اطلاعات حساس مناسب فرض نشد.
- کارت‌های فردی، دعوت تیمی، پنل مدیر و آموزش/Edu، مدت‌های گوناگون و ضمانت‌های متفاوت جدا هستند. null موجودی، به‌خصوص در slot، صفر تلقی نشد ولی تحویل فوری هم تأیید نشد.
- walletCurrency دو حساب Canboso در پاسخ فعلی USD بود. AItoolify هزینه را با your_cost و قیمت‌های USDT می‌دهد؛ برای ToolsMarket/VenteBot برچسب USD بر قرارداد مستند تکیه دارد. USD/USDT تبدیل یا یکسان فرض نشدند؛ قیمت فروش ریالی هنوز محاسبه نشده است.
- چون آدرس پایهٔ دو Canboso یکی است، هویت supplier باید حساب/کلید مستقل را شامل شود. کش یا نگاشت با URL یا نام محصول به‌تنهایی نباید مشترک شود؛ ledger خرید و lookup نیز باید حساب مبدأ را حفظ کنند.

## نگهداری داده و محدودیت بررسی

کلیدها فقط به میزبان ثابت همان فروشنده و در header مستند ارسال شدند؛ برای Canboso نیز x-buyer-key بدون query-string موفق بود. redirect خودکار غیرفعال، بررسی TLS فعال و پاسخ‌ها محدود به اندازه/زمان بودند. headers و مقدار کلیدها چاپ نشدند. پنج درخواست خواندنی بودند؛ سطح مجوز خود کلیدها الزاماً read-only نیست و به‌عنوان credential هزینه‌کردنی باید محافظت شوند.

snapshot و فهرست دقیق قیمت‌ها در پوشهٔ خصوصی کاربر خارج از Git، `.codex/tmp/oosta-supplier-catalogs` ذخیره شدند. گزارش و JSONها secret-redacted و دارای ACL کاربر جاری‌اند؛ CSV خروجی نیز برای جلوگیری از formula injection در دادهٔ تأمین‌کننده escape شد و guardهای آن با assertion بررسی شدند. ارقام wholesale و شرح کامل محصول به repo کپی نشدند.

این بررسی صحت تحویل، دوام اشتراک، تعریف ضمانت، رفتار replay/retention، تطابق مبلغ نهایی خرید با کاتالوگ یا موجودی در زمان پرداخت را ثابت نمی‌کند. هیچ mapping تأییدشده، خرید خودکار یا اتصال production ایجاد نشد. `npm run verify` و build در این مرحلهٔ صرفاً خواندنی اجرا نشدند و ادعای تغییر یا تکمیل قابلیت برنامه مطرح نیست.
