# اتصال رایگان نوسان

کاربر هزینهٔ اشتراک را نپذیرفت و کلید آزمایشی سه‌ماهه با سقف ۱۲۰ درخواست ماهانه را ارائه کرد. کلید خارج از Git و خروجی عمومی نگهداری می‌شود. fallback پولی، تمدید خودکار یا scraping اجرا نشده است.

## رفتار

فقط HTTPS ثابت `api.navasan.tech/latest/` با redirect مسدود، timeout دوازده ثانیه و سقف پاسخ یک مگابایت استفاده می‌شود. نمادهای `usd_sell` و `usdt` به‌صورت مستقل از تومان به ریال تبدیل می‌شوند؛ نبود تتر باعث جایگزینی دلار نیست. زمان اصلی هر ارز حفظ می‌شود. نرخ بیش از یک دقیقه آینده یا بیش از ۱۰ ساعت قدیمی کنار گذاشته می‌شود؛ زمان دریافت، عمر نرخ را صفر نمی‌کند.

یک تلاش مشترک هر ۸ ساعت، حدود ۹۳ تلاش در ماه ۳۱روزه؛ سقف محلی جداگانه ۱۰۰ تلاش در پنجرهٔ شناور ۳۱روزه است. رزرو تلاش زیر قفل دیتابیس پیش از شبکه commit می‌شود. خطا و مرگ فرایند هم سهمیه مصرف می‌کنند. ری‌استارت و هم‌زمانی آن را صفر نمی‌کنند. استعلام مشتری هرگز FX را دریافت نمی‌کند. این آمار فقط مصرف این نصب است؛ استفاده از همان کلید در جای دیگر در شمارندهٔ محلی دیده نمی‌شود.

نرخ رایگان فقط برای برآوردِ دارای زمان منبع استفاده می‌شود و در پنل/استعلام صریحاً نمونه‌برداری‌شده است. اعتبار ۶۰ثانیه‌ای استعلام، نرخ چندساعته را لحظه‌ای نمی‌کند. فرمول کاربر قیمت ارزی × ۱٫۳۰، سپس تبدیل است؛ کف سود ریالی صفر است. خرید خارجی و پذیرش این برآورد برای پرداخت همچنان مسدودند.

۴۰۱/۴۰۳ دریافت بعدی را متوقف می‌کند. پایان دورهٔ محلی سه‌ماهه هم دریافت و استعلام خودکار را می‌بندد؛ تاریخ ابطال واقعی در اختیار ارائه‌دهنده است و ممکن است زودتر باشد. تعویض کلید به‌تنهایی نباید شمارنده را پاک کند.

## مسیر و امنیت

فرم مدیر → schema با rateSource → تنظیم خصوصی → snapshot نرخ → محاسبه → DTO زمان نرخ. نقش فعلی مدیر در دیتابیس و no-store حفظ شده‌اند. snapshot و دفتر مصرف در SiteSetting خصوصی `fx.navasan.free` هستند؛ whitelist تنظیمات عمومی آن‌ها را منتشر نمی‌کند. کلید در JSON تنظیمات، DTO، فرانت و خطاها قرار نمی‌گیرد. URL upstream به دلیل قرارداد سرویس دارای کلید است و هرگز log نمی‌شود.

scheduler فقط در entry point واقعی API شروع می‌شود؛ createApp در تست آن را راه نمی‌اندازد. مسیر پرداخت، مالکیت سفارش/تیکت، تحویل و بازپرداخت تغییر نکرده‌اند و رگرسیون‌های موجود آن‌ها اجرا شدند. فایل کلید روی VPS root-owned و mode 600 است و read-only در کانتینر mount می‌شود؛ داخل release/image نیست.

## شواهد

- یک درخواست واقعی فقط‌خواندنی HTTP ۲۰۰ داد و ۳۰۲ نماد داشت؛ فقط دلار فروش و تتر ذخیره شدند. زمان دریافت `2026-11-07T12:01:36.507Z`؛ همان پاسخ و یک مصرف آن برای ورود به سرور آماده شدند. تست‌ها هیچ درخواست واقعی دیگری نمی‌فرستند.
- fx-contracts: واحد، زمان، دادهٔ خراب/قدیمی/آینده، ارز ناقص، فاصله/سقف، HTTPS و خطای بدون کلید. ابتدا به علت نبود پیاده‌سازی شکست خورد و سپس پاس شد.
- fx-regressions فقط در test:isolated: هشت worker هم‌زمان یک درخواست، حفظ مصرف در اجرای بعدی، تلاش ناموفق، سقف مصرف و توقف ۴۰۱، رد کاربر عادی، عدم نشت عمومی، محاسبهٔ ۳۰٪ و رد نرخ منقضی بدون شبکه.
- تست دیتابیس ایراد deserialize خروجی void قفل را پیدا کرد؛ queryRaw برای قفل نهایی به executeRaw تغییر کرد و تست پاس شد.
- fx-ui-contracts ابتدا نبود وضعیت نرخ رایگان را نشان داد؛ پس از افزودن منبع، زمان و سهمیه پاس شد.
- npm run verify، ESLint فایل‌های API/اسکریپت درگیر، lint وب و build تولید پاس شدند. هر دو audit کامل و production صفر یافته داشتند؛ گزارش JSON در همین پوشه است. وابستگی جدیدی اضافه نشد.
- بازبینی مستقل در quota، خطا، تازگی، واحد، مجوز، cache و startup ایراد مهمی گزارش نکرد؛ بازبین دادهٔ خصوصی یا API واقعی را نخواند/فراخوانی نکرد.

## عملیات و حدود

انتشار با نگه داشتن imageهای قبلی و backup اختصاصی PostgreSQL انجام می‌شود. یک مصرف اولیه قبل از شروع scheduler وارد می‌شود تا دریافت دوم ایجاد نشود. مهاجرت افزودنی تنوع محصول از مرحلهٔ قبلی هم در release هست؛ دیتابیس کاری برای تست reset یا seed نمی‌شود. نتیجهٔ واقعی انتشار جداگانه در ادامه ثبت می‌شود.

restore یک backup قدیمی یا حذف دفتر مصرف، آمار را عقب می‌برد؛ در restore باید آخرین دفتر مصرف حفظ و با مصرف ارائه‌دهنده تطبیق داده شود. نرخ مرجع، تضمین قیمت اجرای معامله یا هزینهٔ واقعی شارژ کیف پول نیست. تست محلی و audit تضمین بی‌باگ بودن کل سامانه نیستند.


## نتیجهٔ انتشار واقعی

نسخهٔ `/opt/oostaAI/releases/20261107-free-fx` فعال شد و current به آن اشاره می‌کند. هر دو image روی VPS ساخته شدند. imageهای قبلی با تگ `before-free-fx-20261107` و backup خصوصی `pre-free-fx-20261107.dump` نگه داشته شدند. فقط کانتینرهای Oosta API و وب بازسازی شدند؛ PostgreSQL و سرویس‌های دیگر برای این انتشار متوقف نشدند. migration افزودنی مرحلهٔ تنوع در startup API اجرا شد.

API مدیر در سرور با حساب مدیر موجود HTTP ۲۰۰ و `private, no-store` داد: منبع NAVASAN_FREE، درصد ۳۰، هر دو ارز USD و USDT و مصرف همچنان یک درخواست. زمان نمونهٔ اولیه حفظ شد؛ نوبت بعدی محلی `2026-11-07T20:01:36.507Z` است. کلید در پاسخ دیده نشد. فایل خصوصی mode 600 و mount آن read-only است.

اسکریپت بررسی HTTP پیش‌نمایش از داخل VPS، دامنهٔ عمومی، دارایی استاتیک، احراز هویت، no-store، منع نوشتن و اعتبارسنجی ورود را با موفقیت بررسی کرد. تلاش اولیه از رایانهٔ محلی با خطای DNS EAI_AGAIN مواجه شد؛ TLS یا حفاظت DNS غیرفعال نشد. این بازبینی شامل screenshot جدید مرورگری پنل نیست؛ قرارداد SSR رابط و بررسی HTTP واقعی جداگانه انجام شده‌اند.

فروش خودکار هنوز فعال نشده و منابع واقعی فروشنده هنوز نیازمند اتصال تنوع‌های تأییدشده هستند. فعال شدن دریافت ارز به معنای آماده بودن مسیر پرداخت/خرید/تحویل خارجی نیست.
