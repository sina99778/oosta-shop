# تغییر مبنای سود به قیمت ارزی

کاربر ۳۰٪ افزایش روی قیمت دلاری تأمین‌کننده را انتخاب کرد؛ این تصمیم جای پیشنهاد قبلی درصد و کف سود ریالی را می‌گیرد.

فرمول فعلی: `قیمت تأمین‌کننده در USD یا USDT × (۱ + درصد / ۱۰۰) × نرخ همان ارز + هزینهٔ ثابت ریالی`. گرد کردن فقط یک بار در پایان و رو به بالا به تومان کامل انجام می‌شود؛ واحد API همچنان ریال است. نرخ USD و USDT مستقل‌اند. هزینهٔ ثابت، در صورت تنظیم صریح مدیر، مشمول افزایش درصدی نیست و پیش‌فرض آن صفر است.

فرم قیمت‌گذاری در نبود سیاست ذخیره‌شده، درصد ۳۰ و هزینهٔ ثابت صفر دارد؛ فعال‌سازی و نرخ ارز همچنان نیازمند تنظیم معتبر مدیر است. API برای جلوگیری از اعمال کف سود ریالی، فقط مقدار صفر را برای فیلد سازگاری `minimumProfitIrr` می‌پذیرد. سیاست قدیمی با کف سود غیرصفر قابل خواندن/استعلام نیست و باید از پنل مجدد ذخیره شود؛ نرخ یا قیمت حدسی جایگزین آن نمی‌شود. تنظیمات ذخیره‌شدهٔ معتبر مدیر بدون اجازه بازنویسی نشده‌اند.

مثال بدون کارمزد: خرید ۱۰ دلار به قیمت فروش ۱۳ دلار می‌رسد، سپس تبدیل می‌شود. با نرخ یکسان و بدون هزینهٔ اضافه، افزودن درصد پیش و پس از تبدیل از نظر ریاضی برابر است؛ اختلاف مهم این تغییر، حذف کف سود ریالی و نگرفتن درصد از کارمزد ریالی است. ۳۰٪ افزایش روی خرید، حدود ۲۳٫۰۸٪ از مبلغ فروش است، پیش از هزینه‌های دیگر.

## بررسی مسیرها و تست

مسیر بررسی‌شده: فرم مدیر → PATCH خصوصی قیمت‌گذاری → schema → ذخیرهٔ خصوصی → getPricing → indicativePrice → DTO استعلام. کنترل نقش فعلی مدیر، no-store، انقضای نرخ، جدایی ارزها، منع خرید خارجی و عدم افشای قیمت عمده حفظ شده است. مسیر سفارش/تحویل/بازپرداخت تغییر نکرده است.

تست ابتدا نشان داد کد قبلی روی هزینهٔ ثابت ریالی هم درصد می‌گرفت: خرید ۱۰ دلار، نرخ ۱٬۰۰۰٬۰۰۰ ریال، افزایش ۳۰٪ و هزینهٔ ثابت ۱۰۰٬۰۰۰ ریال، به‌جای ۱۳٬۱۰۰٬۰۰۰ مقدار ۱۳٬۱۳۰٬۰۰۰ می‌داد. تست جداگانه نشان داد کف سود غیرصفر پذیرفته می‌شد. هر دو پس از اصلاح پاس شدند. تست HTTP دیتابیس موقت، ۳۰٪ برای دو منبع، رد کف سود غیرصفر و رد تغییر سیاست توسط کاربر عادی را نیز پوشش می‌دهد.

تأیید نهایی: `npm run verify`، ESLint فایل‌های API/تست درگیر، lint وب و `npm run build`. تست‌های دیتابیس فقط با `test:isolated` انجام می‌شوند؛ کاربر/درگاه/کاتالوگ مصنوعی و شبکهٔ تأمین‌کننده stub است. وابستگی جدیدی اضافه نشده است؛ گزارش audit مرحلهٔ قبل در همین پوشه قرار دارد.

این تغییر محلی است؛ انتشار روی VPS، تنظیم نرخ لحظه‌ای، خرید واقعی یا تغییر تنظیمات زنده انجام نشده است. تضمین سود خالص یا پوشش همهٔ نوسانات ارز از این درصد نتیجه نمی‌شود.
