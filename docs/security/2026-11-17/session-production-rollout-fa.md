# اصلاح تکمیلی و آزمون زندهٔ نشست — ۲۰۲۶-۱۱-۱۷

ادامهٔ [سخت‌سازی نشست](login-session-hardening-fa.md). دامنهٔ این گزارش ورود، تغییر رمز، خروج و سازگاری انتشار با کاتالوگ است؛ نتیجهٔ آن تضمین امنیت کل سامانه نیست.

## ایرادها و اصلاح

- فرم cross-origin می‌توانست با login کوکی مرورگر را جایگزین کند. در login، signup و logout، Origin بیگانه یا `null` و Referer بیگانه اکنون رد می‌شوند. نبود هر دو در login/signup برای سازگاری کلاینت‌های غیرمرورگری مجاز است. نوشتن احراز‌شده با کوکی همچنان Origin/Referer معتبر می‌خواهد. Origin صریح `null` دیگر به Referer برنمی‌گردد.
- دو تغییر رمز هم‌زمان، بعد از بررسی همان رمز قدیمی، امکان بازنویسی هم را داشتند. به‌روزرسانی اکنون به hash و sessionVersion خوانده‌شده مشروط است؛ درخواست بازنده خطای `CREDENTIALS_CHANGED` می‌گیرد و رمز برنده حفظ می‌شود.
- پاسخ دیررس `/auth/me` می‌توانست ورود جدید را بازنویسی کند. نسل نشست در AuthProvider مانع اعمال پاسخ قدیمی می‌شود.
- نشانگر نشست قبلاً برای همان کاربر تکرار می‌شد؛ یک 401 دیررس سفارش می‌توانست نشست تازهٔ تغییر رمز را پاک کند. نشانگر هر نسل متفاوت است و هرگز به API فرستاده نمی‌شود.
- خروج ناموفق قبلاً در فرانت موفق نمایش داده می‌شد، با وجود باقی‌ماندن کوکی HttpOnly. اکنون فقط پس از موفقیت API وضعیت حساب پاک می‌شود؛ دکمه در حال ارسال غیرفعال و خطای قابل‌تلاش‌مجدد نمایش داده می‌شود.

مسیر فرانت (`lib/api.ts`، AuthProvider، هدر و فرم امنیت)، DTOهای ورود/تغییر رمز، Zod، middleware کوکی/نقش جاری و کنترلر و سرویس با هم بررسی شدند. دادهٔ حساس جدیدی به پاسخ کاربر اضافه نشد. مسیرهای خصوصی همچنان no-store هستند؛ منطق سفارش، پرداخت و تحویل تغییر نکرد.

## شواهد محلی

- regression فرم بیگانه پیش از اصلاح شکست خورد: پاسخ 200 به‌جای 403. بازنویسی هم‌زمان رمز در بازبینی با Prisma ساختگی بازتولید شد؛ آزمون هم‌زمان روی دیتابیس یک‌بارمصرف اکنون فقط یک برنده را می‌پذیرد و ورود با رمز بازنده را رد می‌کند.
- سه آزمون واقعی Edge روی خروجی standalone ساخت production، پیش از اصلاح شکست خوردند و پس از اصلاح موفق شدند: hydration دیررس، خروج با پاسخ 503 و 401 دیررس بعد از تغییر رمز. پاسخ‌های API ساختگی‌اند؛ خرید، پرداخت، مدل پولی یا پیام تلگرام در این آزمون‌ها فراخوانی نمی‌شود.
- `npm run verify`: exit 0؛ شامل typecheck، dependency، contracts، security و دیتابیس یک‌بارمصرف. دیتابیس کاری seed/reset نشد. خروجی timeout تراکنش در سناریوی شکست کنترل‌شده ظاهر شد؛ runner با PASS و exit 0 تمام شد.
- ESLint فایل‌های تغییرکردهٔ API و اسکریپت مرورگر، به‌همراه `npm run lint -w @oosta/web`: موفق.
- `npm run build`: API و Next.js موفق. build و verify به‌صورت متوالی اجرا شدند.
- `npm audit --omit=dev` و `npm audit`: هر دو صفر آسیب‌پذیری گزارش کردند. تلاش اول به‌دلیل زنجیرهٔ CA محیط شکست خورد؛ با `NODE_USE_SYSTEM_CA=1` و بدون خاموش‌کردن اعتبارسنجی TLS تکرار شد.
- `git diff --check`: موفق.

اجرای مجدد مرورگر در Windows، پس از build:

```powershell
node scripts/auth-browser-regressions.cjs hydration
node scripts/auth-browser-regressions.cjs logout
node scripts/auth-browser-regressions.cjs late401
```

## انتشار و بررسی عمومی

- release فعال: `/opt/oostaAI/releases/20261117-session-race-fixes`؛ نسخهٔ پایه `/opt/oostaAI/releases/20261117-login-session` حفظ شد. فقط شش فایل اجرایی اصلاح‌شده روی همان نسخه overlay شدند تا تغییرات اخیر SEO و nginx حفظ شوند.
- ایمیج‌های برگشت: `oosta-api:pre-session-race-fixes` و `oosta-web:pre-session-race-fixes`. انتشار health gate و برگشت خودکار در صورت شکست آزمون داشت. API و web ساخته و جایگزین شدند؛ سپس symlink فعلی تغییر کرد.
- migration جدید، seed/reset یا تغییر nginx در این اصلاح وجود نداشت. `nginx -t` موفق بود. include قبلی مسیرهای مدیریت نشست حفظ شد.
- آزمون مستقیم روی HTTPS عمومی با کاربر USER ساختگی و رمز تصادفی در حافظه انجام شد. حساب پس از آزمون شرطی بر id/email/role حذف شد؛ هیچ رمز، JWT یا کوکی در خروجی چاپ نشد.
- تأیید شد: login و `/auth/me` موفق؛ کوکی دارای Secure/HttpOnly/SameSite=Lax؛ دسترسی USER به admin ردشده؛ login/logout/change-password از مبدأ بیگانه یا null ردشده؛ رمز فعلی اشتباه 400 و حفظ نشست؛ تغییر رمز و ابطال کوکی و Bearer قدیمی؛ logout-all و ابطال دستگاه دیگر؛ logout و حذف کوکی؛ signup عمومی همچنان 503.
- بررسی مکمل عمومی: ۲۴ صفحهٔ اول کاتالوگ دارای پاسخ 200، هدر index/follow، canonical و JSON-LD؛ robots و sitemap با دامنهٔ واقعی؛ orders/tickets/admin بدون نشست 401 و no-store؛ فایل fingerprinted فرانت immutable.

## آمادگی فروش و محدودیت

- snapshot عمومی این دور: ۹۷ محصول، ۸۹ محصول با `SUPPLIER_STOCK` و مجموع موجودی داخلی صفر. این عدد موجودی ذخیره‌شدهٔ تأمین‌کنندگان است و تضمین تحویل لحظهٔ خرید نیست.
- تنظیمات عمومی پرداخت: `online=false` و `cardToCard=false`. فروش عمومی فعال نشد و خرید تأمین‌کننده یا خرج واقعی انجام نشد.
- آزمون UI مرورگر در این دور روی build محلی و پاسخ ساختگی بود؛ آزمون HTTPS عمومی با HTTP client و حساب ساختگی انجام شد. Safari/Firefox و ورود با حساب واقعی ادمین آزموده نشدند.
- logout معمولی کوکی همان مرورگر را حذف می‌کند؛ Bearer کپی‌شده را به‌تنهایی باطل نمی‌کند. تغییر رمز یا logout-all برای ابطال همه نشست‌هاست.
- بازیابی رمز، 2FA، scope/expiry کلیدهای API و تکمیل CSP همچنان کار جداگانه‌اند. دسترسی به فروش واقعی به انتخاب محصول قابل‌تحویل و فعال‌سازی مسیر پرداخت پس از آزمون خودش نیاز دارد.
