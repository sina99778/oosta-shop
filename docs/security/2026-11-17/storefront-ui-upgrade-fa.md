# ارتقای رابط فروشگاه (سرمه‌ای/نعنایی) — 2026-11-17

هدف: صیقل دادن همان جهت تأییدشدهٔ سرمه‌ای و نعنایی، بدون عوض کردن هویت. ورودی کار:
- نقد طراحی سایت زنده، روی موبایل و دسکتاپ
- اسکن خودکار دسترس‌پذیری صفحه‌های `/fa`، `/fa/products`، `/fa/products/chatgpt` و `/fa/login`
- خواندن کد

## یافته‌ها

- **کارت محصول:** در هر کارت سه چیز تکراری با یک وزن پشت هم می‌آمد: دسته، نشان موجودی و «قیمت با استعلام». دکمهٔ خاکستری «مشاهدهٔ پلن‌ها» هم با بقیهٔ کارت رقابت می‌کرد. نشانه‌ای برای hover و focus کیبورد روی خود کارت نبود.
- **صفحهٔ ورود و ثبت‌نام:** یک کارت سفید روی زمینهٔ تقریباً سفید بود، بدون هیچ نشانی از برند.
- **اندازهٔ هدف لمسی:** لینک‌های مسیر صفحه (breadcrumb) ۲۳×۲۵ پیکسل بودند و لینک «ثبت‌نام» در صفحهٔ ورود ۴۴×۲۲.
- **کنتراست:** متن «فقط N عدد مانده» با رنگ `#ef4444` روی سفید کنتراستی حدود 3.8:1 داشت، که برای متن ۱۳ پیکسلی کمتر از حد AA (4.5:1) است.
- **رنگ‌های تکراری:** سرمه‌ای `#101d2e` و نعنایی `#b7ecd8` در ۲۲ جای فایل‌های CSS دستی نوشته شده بودند.
- **موارد سالم:** landmarkها، یک H1 در هر صفحه، لینک پرش به محتوا، `alt` تصاویر و برچسب فرم‌ها مشکلی نداشتند. `select`هایی که اسکن علامت زد داخل یک `<details>` بسته بودند؛ آن‌ها برچسب دارند و هشدار اشتباه بود.

## تغییرات

- **توکن‌ها:** `--c-navy`، `--c-mint` و `--c-danger-text` (روشن `#b91c1c`، تیره `#fca5a5`) در `globals.css` تعریف شدند. CSS ماژول‌ها حالا از همین توکن‌ها استفاده می‌کنند.
- **کارت محصول** (`product-card.tsx`، `shop.module.css`):
  - موجودی به‌صورت یک چیپ با نقطهٔ وضعیت روی تصویر آمد. نقطه برای موجودی فروشگاه سبز است.
  - دسته به‌شکل برچسب کوچک بالای نام محصول آمد.
  - پایین کارت یک خط‌چین و فلش دایره‌ای اضافه شد.
  - با hover، کارت کمی بالا می‌آید، سایه می‌گیرد و تصویر کمی بزرگ‌تر می‌شود.
  - focus کیبورد حلقهٔ واضح دارد.
  - با `prefers-reduced-motion` حرکت‌ها خاموش می‌شوند.
  - در موبایل، آیکون پیش‌فرض محصول پایین‌تر آمد تا زیر چیپ نرود.
  - متن‌هایی که تست‌های قرارداد بررسی می‌کنند تغییر نکرد.
- **ورود و ثبت‌نام** (`auth-form.tsx`، `auth.module.css`):
  - صفحه دو ستون شد: یک پنل سرمه‌ای برند و فرم کنار آن. در موبایل پنل به یک نوار کوتاه بالای فرم تبدیل می‌شود.
  - ادعاهای پنل فقط چیزهایی است که سیستم واقعاً انجام می‌دهد: داشبورد سفارش، تیکت پشتیبانی، و باطل شدن نشست‌های دیگر با تغییر رمز.
  - دکمهٔ نمایش و پنهان کردن رمز اضافه شد، با `aria-pressed`، `aria-label`، `aria-controls` و ابعاد ۴۴×۴۴.
- **دسترس‌پذیری:**
  - لینک‌های مسیر صفحه حداقل ۳۲ پیکسل ارتفاع دارند.
  - جداکننده‌های `/` با `aria-hidden` از صفحه‌خوان پنهان شدند.
  - آیتم آخر مسیر `aria-current="page"` گرفت.
  - لینک ثبت‌نام و ورود ۴۴ پیکسل ارتفاع دارد.

## بررسی‌ها

- **مرورگر، روی کد محلی و دیتابیس یک‌بارمصرف:**
  - کارت‌ها در تم روشن و تیره، دسکتاپ و موبایل بررسی شدند. در عرض ۳۷۵ پیکسل اسکرول افقی نبود و چیپ موجودی بریده نمی‌شد.
  - صفحهٔ ورود در دسکتاپ، موبایل و تم تیره بررسی شد.
  - دکمهٔ نمایش رمز نوع فیلد را عوض کرد و برچسبش را به‌روز کرد.
  - ثبت‌نام با کاربر ساختگی تا داشبورد پیش رفت.
- **دستورها:**
  - `npm run lint` بدون خطا رد شد.
  - `npm run build -w @oosta/web` موفق بود.
  - `npm run verify` پاس شد: ۵۷ خط PASS و `fail 0`.
  - وابستگی‌ای تغییر نکرد.
- **prettier:** چهار فایل از قبل هشدار prettier داشتند و دست نخوردند: `account.module.css`، `admin.module.css`، `journal.module.css` و `journal.tsx`.
