# مبنای موجودی خرید دستی BatmanBot

در خرید دستی تأییدشدهٔ BatmanBot (`ventebot`)، ماندهٔ داخلی کیف پول دیگر سقف تجمعی خرید نیست. API موجودی واقعی دلاری و قیمت همان سفارش را پیش از ارسال خرید بررسی می‌کند. تأیید افزایش قیمت، فعال‌بودن اتصال، رزرو انحصاری کیف پول و جلوگیری از ارسال مجدد خرید مبهم همچنان برقرارند. مسیرهای خودکار و سقف داخلی سایر تأمین‌کنندگان طبق روال قبلی عمل می‌کنند.

رزرو با موجودی واقعی، ماندهٔ داخلی را موقتاً در تنظیمات دیتابیس ثبت می‌کند تا پس از تسویه بازگردد. پیش از بازگشت به نسخهٔ قبلی، رزروهای فعال این مسیر باید تعیین تکلیف شوند. این انتشار مهاجرت دیتابیس ندارد.

- رگرسیون ابتدا انسداد خرید ۳ دلاری با موجودی ۴٫۱۶ دلار و ماندهٔ داخلی ۰٫۱۶ دلار را بازتولید کرد. نسخهٔ اصلاح‌شده در دیتابیس موقت، رد کاربر غیرمجاز، موجودی ناکافی، رزرو هم‌زمان و جلوگیری از سفارش تکراری را پاس کرد.
- `npm run verify`، `npm run lint` و بیلد تولید Docker برای API و وب موفق شدند. هر دو اجرای `npm audit` و `npm audit --omit=dev` هیچ موردی گزارش نکردند.
- انتشار `20261123-batman-live-wallet` با ترتیب API و سپس Web انجام شد. استعلام فقط‌خواندنی از نسخهٔ زنده، موجودی ۱٫۱۶ دلار، فعال‌بودن مبنای جدید و وضعیت تحویل‌شدهٔ سفارش `#dlzc4yq7` را تأیید کرد. بررسی سلامت دیتابیس، دسترسی عمومی وب و رد درخواست بدون نشست به API مدیریت نیز موفق بودند. اولین بررسی انتشار به‌دلیل بارگذاری‌نشدن فایل تنظیمات در فرایند مستقل آزمون بازگشت خورد. پس از اصلاح اسکریپت آزمون، انتشار کامل شد.
- آزمون‌ها هیچ خرید واقعی به تأمین‌کننده ارسال نکردند. API فروشنده سقف مبلغ را هنگام ثبت خرید نمی‌پذیرد، بنابراین استعلام نهایی قیمت تضمین نمی‌کند که مبلغ در فاصلهٔ استعلام و ثبت تغییر نکند.
