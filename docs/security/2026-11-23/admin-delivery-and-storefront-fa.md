# نمایش کد تحویل و هماهنگی ویترین

- در جزئیات سفارش پرداخت‌شده، «نمایش کد تحویل» کد فعال‌سازی، کد هدیه یا متن ثبت‌شده هنگام تحویل را به تفکیک قلم می‌خواند. متن تحویل برخی محصولات، از جمله سفارش Granola، خودش حاوی کد است. این درخواست فقط بعد از انتخاب دکمه ارسال می‌شود. پاسخ با `private, no-store` و فقط برای نشست دارای نقش فعلی مدیر در دسترس است و از کلیدهای API مدیریت پذیرفته نمی‌شود. ایمیل و رمز اکانت در پاسخ این مسیر یا در فهرست سفارش‌ها ارسال نمی‌شوند.
- قراردادهای کاتالوگ، سبد مهمان، فاکتور، کارت‌به‌کارت و نشست برای تغییرات ویترین، سبد و حساب کاربری با نسخهٔ API تطبیق داده شدند. آزمایشگاه پرامپت در مرورگر کار می‌کند.
- آزمون مرورگر در موبایل نشان داد پرش از بالای دکمه به پایین آن می‌تواند وضعیت `IntersectionObserver` را بدون تغییر بگذارد. نوار خرید در موبایل با بررسی حداکثر یک‌بار در هر فریم اسکرول، حتی در این حالت ظاهر می‌شود. رگرسیون پیش از اصلاح شکست خورد و بعد از اصلاح پاس شد.
- آزمون API با دادهٔ ساختگی دسترسی مدیر، رد نشست مشتری و ناشناس، رد کلید API، مسدود کردن سفارش پرداخت‌نشده و عدم ارسال فیلدهای اکانت را پوشش می‌دهد. هیچ خرید، پرداخت، ارسال رسید واقعی یا ارسال اعلان مشتری برای آزمون انجام نشد.
- نسخهٔ نهایی با `npm run verify`، `npm run lint`، هر دو دستور `npm audit` و بیلد تولید API و وب بررسی شد. Edge با بک‌اند ساختگی، باز و بسته‌کردن کد در عرض ۳۹۰ و ۱۳۶۶، مسیر ورود و انتقال سبد مهمان، خطای ظرفیت و تلاش دوباره، تازه‌کردن فاکتور منقضی، پیگیری و ثبت رسید و بازآوری وضعیت، صفحات بازیابی و آزمایشگاه پرامپت را بررسی کرد.
- در انتشار `20261123-delivery-codes`، API پیش از وب جایگزین شد. بررسی فقط‌خواندنی روی سرور وجود متن تحویل در سفارش `#dlzc4yq7` را بدون چاپ محتوا تأیید کرد. درخواست ناشناس به مسیر جدید روی دامنهٔ عمومی با `401` و `no-store` رد شد. خانه، کاتالوگ، سبد، بازیابی رمز، پوستهٔ مدیریت و سلامت دیتابیس پاسخ دادند. مهاجرت و بازسازی PostgreSQL انجام نشد. نشست واقعی مدیر در مرورگر و ارسال واقعی ایمیل یا پرداخت در این نوبت آزمایش نشدند.
