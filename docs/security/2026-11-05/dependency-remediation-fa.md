# رفع هشدارهای وابستگی — ۵ نوامبر ۲۰۲۶

دو زنجیرهٔ هشدار checkpoint قبلی با override نسخه‌های دقیق اصلاح شدند. Prisma و client روی 6.19.3 و Next روی 16.4.5 باقی ماندند. طراحی تأییدشدهٔ سرمه‌ای/نعنایی و قراردادهای HTTP تغییر نکردند.

## تغییر و شاهد

- `deepmerge-ts`: نسخهٔ 7.1.5 مصرف‌شده توسط `@prisma/config` به 8.0.0 منتقل شد. تست `audit-prisma-merge.cjs` پیش از اصلاح با `Maximum call stack size exceeded` شکست خورد و پس از آن موفق شد؛ ادغام تنظیمات تودرتو نیز بررسی می‌شود.
- matcher مصرف‌شده توسط TypeScript ESLint از `minimatch@10.2.6` به 11.0.1 منتقل شد. تست جدید قبل از اصلاح، نسخهٔ آسیب‌پذیر مصرف‌کنندهٔ واقعی را رد کرد؛ بعد از اصلاح، الگوهای فایل TypeScript، مسیر مخفی و موارد خارج از الگو را بررسی می‌کند. این تست بازتولید حملهٔ DoS نیست؛ تلاش محدود برای بازتولید آن در این محیط مصرف غیرعادی را اثبات نکرد.
- `@prisma/config@6.19.3` به‌عنوان وابستگی مستقیم توسعه برای تست loader ثبت شد. بدون این ثبت، npm 11.13.0 در این workspace با وجود نصب نسخهٔ اصلاح‌شده، رابطهٔ transitive را در `npm ls` نامعتبر گزارش می‌کرد. اکنون `npm ls deepmerge-ts minimatch` با خروجی صفر، نسخه‌های overrideشده را نشان می‌دهد.
- تست loader واقعی Prisma، تنظیمات ساختگی تودرتو را می‌خواند و مسیر خطای فایل تنظیمات گمشده را هم بررسی می‌کند. این تست به DB وصل نمی‌شود و دستور seed داخل fixture را اجرا نمی‌کند.
- فرمان `test:dependencies` به `verify` اضافه شد تا بازگشت به نسخهٔ قدیمی یا ناسازگاری ادغام، بررسی‌های معمول را متوقف کند.
- lockfile با حفظ نسخهٔ سایر پکیج‌ها به‌روز شد؛ نصب تمیز در پوشهٔ موقت جدا بررسی شد. `npm install --package-lock-only` نیز نسخه‌های اصلاح‌شده را حفظ کرد. هیچ کد vendor یا فایل داخل node_modules به‌صورت دستی patch نشد.

## نتایج بررسی

- `npm run verify`: موفق؛ TypeScript هر دو workspace، تست‌های وابستگی، قرارداد رندر فرانت، cache خصوصی، خطای احراز هویت و کنترل‌های امنیتی.
- `test:isolated` در همان verify: هر ۱۴ migration، **۱۵۲ بررسی smoke** و regressionهای رقابت پرداخت/موجودی، بازپرداخت، مالکیت، نقش فعلی DB، محدودیت رسید و restore موفق شدند. DB موقت در پایان حذف شد.
- `npm run build`: API و وب موفق؛ ۴۷ صفحه در production build وب تولید شد.
- ESLint دو اسکریپت وابستگی موفق شد.
- نصب تمیز جداگانه با `npm ci --ignore-scripts` و سپس `npm ci --omit=dev --ignore-scripts` موفق شد؛ در هر دو نصب، `npm ls` و ادغام حلقوی با dependency واقعی Prisma موفق بودند. lifecycle scriptها در این آزمایش نصب اجرا نشدند؛ build و migrationها جداگانه با مجموعهٔ verify بررسی شدند.
- بازبینی مستقل diff، مصرف‌کنندگان و مدارک ایراد قابل‌اقدامی پیدا نکرد؛ تست وابستگی و `npm ls` را هم دوباره اجرا کرد.
- `npm audit --omit=dev --json`: خروجی صفر و **صفر هشدار شناخته‌شده**؛ شاهد `npm-audit-production-after.json`.
- `npm audit --json`: خروجی صفر و **صفر هشدار شناخته‌شده**؛ شاهد `npm-audit-after.json`.

مصرف‌کنندگان تغییرکرده loader تنظیمات Prisma و matcher ابزار lint هستند. DTO، schema اعتبارسنجی HTTP، migration و مجوز endpoint جدیدی اضافه نشده است. مسیرهای فرانت/API و حالت‌های دسترسی غیرمجاز، no-store، پرداخت تأییدشدهٔ منتظر تحویل و عدم افشای سفارش بازپرداخت‌شده با مجموعهٔ جاری دوباره بررسی شدند. پرداخت، پیام‌رسانی و مدل واقعی در تست‌ها استفاده نشدند؛ DB کاری seed یا reset نشد.

## محدودیت‌ها و ادامه

- overrideها major وابستگی transitive را تغییر می‌دهند؛ سازگاری برای مصرف فعلی پروژه و loader آزمایش شده است، نه تمام قابلیت‌های Prisma یا deepmerge. در تغییرات آیندهٔ ORM یا ساختار تنظیمات باید دوباره بازبینی شوند؛ پس از انتشار نسخهٔ سازگار upstream حذف آن‌ها بررسی شود.
- npm هنگام نصب برای `eslint@9.39.5` پیام deprecated داد. این پیام advisory امنیتی در audit فعلی نیست. مهاجرت major ابزار lint در این تغییر انجام نشد.
- صفر بودن audit فقط نتیجهٔ پایگاه هشدار npm در زمان بررسی است؛ تضمین نبود باگ یا امنیت استقرار نیست.
- مرحلهٔ بعد، بازبینی تنظیمات واقعی محیط staging، backup/restore عملیاتی و آزمون سرتاسری روی محیط مستقر با درگاه آزمایشی است. TLS/CDN، سرور production، پرداخت واقعی و اعلان واقعی در این مرحله بررسی عملی نشدند.
