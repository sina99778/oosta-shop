# استقرار پیش‌نمایش روی VPS — ۵ نوامبر ۲۰۲۶

پیش‌نمایش در `https://oostaai.store/fa` روی سرور `91.107.254.140` اجرا شد. کاربر دامنه، ایمیل مدیر و باقی‌ماندن در حالت پیش‌نمایش را تأیید کرد. این مرحله فعال‌سازی فروش واقعی نیست.

## استقرار و مرز دسترسی

- مسیر release: `/opt/oostaAI/releases/20261105-first-deploy`؛ لینک جاری `/opt/oostaAI/current`؛ پروژهٔ Compose با نام `oosta` و volume جدید `oosta_pgdata`.
- کد مبتنی بر checkpoint `1859252` به‌همراه اصلاحات محلی وابستگی و استقرار است؛ این تغییرات جدید هنوز commit/push نشده‌اند. انتقال source به‌صورت آرشیو فیلترشده انجام شد؛ env، کلید، node_modules، build خروجی ویندوز و ChatExport منتقل نشدند.
- host Nginx موجود حفظ شد؛ فقط site جدید `oostaai.store` اضافه شد. API روی `127.0.0.1:4400`، فرانت روی `127.0.0.1:3400`؛ DB هیچ پورت host ندارد. استک‌های قبلی در پایان همچنان uptime قبلی و وضعیت healthy داشتند.
- سقف حافظهٔ API/DB هرکدام ۲۵۶ و وب ۳۸۴ MiB؛ مصرف مشاهده‌شده پس از startup حدود ۵۲/۵۲/۷۵ MiB. Oosta restart=0 و OOM=false بود. برای ساخت روی سرور مشترک کم‌حافظه، swap اختصاصی ۲ GiB در shared فعال شد؛ در fstab ثبت نشده است.
- secretهای JWT و DB تصادفی، فقط روی سرور در shared و mode 600 تولید شدند. هیچ secret محلی توسعه به محیط منتشرشده کپی نشد. `.dockerignore` نیز envهای production و فایل‌های کلید/backup را حذف می‌کند.
- گواهی مبدأ Let's Encrypt برای دامنه صادر شد؛ انقضا ۲۰۲۷-۰۲-۰۳. renewal خودکار و reload hook با `nginx -t` موجود است. وبروت ACME `/var/lib/oosta-acme` حفظ شد.
- کاربر اتصال آروان به مبدأ را روی HTTPS/443 و اعتبارسنجی گواهی با SNI دامنه تنظیم کرد. درخواست عمومی login با بدنهٔ خالی اکنون از guard عبور کرده و پاسخ اعتبارسنجی 400 می‌گیرد؛ مبدأ HTTPS نیز جداگانه با بررسی گواهی موفق شد.
- ایراد یافت‌شده در review: login روی HTTP قابل ارسال بود. قبل از اصلاح، درخواست خالی HTTP به API می‌رسید و 400 می‌گرفت. پس از guard روی **scheme واقعی Nginx**، HTTP برابر 503 و HTTPS معتبر برابر 400 شد؛ ادعای X-Forwarded-Proto به‌تنهایی این guard را باز نمی‌کند.
- پیش‌نمایش همهٔ mutationها را در proxy مسدود می‌کند، جز login معتبر روی HTTPS. ثبت‌نام، ویرایش مدیر، سفارش و payment verification همچنان 503 هستند. API با mock برای این محیط کنترل‌شده اجرا می‌شود؛ این گزینه مجوز فروش عمومی نیست و نباید API loopback مستقیماً منتشر شود.
- حساب ADMIN با ایمیل تأییدشده و bootstrap بدون reset ساخته شد. رمز تصادفی در فایل خصوصی سرور و فایل خصوصی خارج از repo روی رایانهٔ کاربر ذخیره شد و در گزارش/چت چاپ نشد. HTTP testها از رمز واقعی استفاده نکردند. DB در پایان: ۱ کاربر، صفر محصول، صفر سفارش؛ demo seed اجرا نشد.
- Telegram، مدل‌ها و پرداخت واقعی خاموش‌اند. backup اولیه با pg_dump فرمت custom در shared/backups ثبت شد و فهرست archive با pg_restore خوانده شد؛ restore روی DB منتشرشده اجرا نشد.

## شواهد بررسی

- `npm run verify`: موفق، شامل TypeScript، loader/matcher، قرارداد فرانت/API، cache خصوصی، access denied و DB موقت با ۱۴ migration، ۱۵۲ بررسی smoke و regressionهای پرداخت/موجودی/restore. DB کاری برای این تست‌ها استفاده نشد.
- ساخت واقعی Docker لینوکس API (Prisma generate + TypeScript) و وب (Next production، ۴۷ صفحه) موفق شد. یک wrapper اولیهٔ PowerShell بعد از موفقیت build خطای exit quoting داشت؛ فرمان صحیح بعدی با exit 0 و artifact واقعی بررسی شد.
- `npm audit --omit=dev` و `npm audit` هنگام این مرحله: صفر هشدار شناخته‌شده. این بررسی اسکن CVE بسته‌های سیستم‌عامل image نیست.
- ESLint اسکریپت‌های تغییرکرده موفق شد. یک escape زائد در regex تست جدید در اولین lint شناسایی و پیش از بررسی نهایی حذف شد.
- `node scripts/preview-http-check.cjs https://oostaai.store --login-ready`: موفق. صفحه/asset، API و DB health، catalog/login، 401 سفارش/تیکت/مدیر با no-store، 503 mutationها از جمله مسیرهای encoded/دو اسلش و 404 فایل env بررسی شدند. پاسخ عمومی دارای preview marker، noindex و frame protection است.
- `nginx -t` موفق. گواهی مبدأ با curl --resolve و verification معمول TLS بررسی شد. guard ورود HTTP و validation ورود HTTPS هر دو مستقیماً از سرور بررسی شدند.
- بازبینی مستقل یک ایراد HTTP login را یافت؛ پس از اصلاح و بازبینی مجدد، ایراد قابل‌اقدام دیگری در محدودهٔ تغییرات نیافت.

## محدودیت‌ها و ادامه

- کاتالوگ عمداً خالی است؛ اطلاعات محصولات و موجودی واقعی باید قبل از فروش وارد و بررسی شوند. مدیر فعلاً فقط ورود و مشاهده دارد؛ نوشتن از پنل همچنان بسته است.
- merchant واقعی، پرداخت/بازپرداخت واقعی، اعلان واقعی و فراخوانی مدل تست نشدند. تأیید امنیت کل سرور یا تضمین نبود باگ از این نتایج به دست نمی‌آید.
- backup اولیه فقط محلی است؛ زمان‌بندی و مقصد off-server، آزمون بازیابی عملیاتی جداگانه و سیاست نگهداری قبل از فروش لازم‌اند.
- بازگردانی IP واقعی مشتری از CDN هنوز در host Nginx تنظیم نشده است؛ header ورودی جعل‌شده بازنویسی می‌شود، اما محدودیت نرخ می‌تواند بین کاربران یک POP مشترک شود. قبل از فعال‌سازی عمومی باید CIDR رسمی/به‌روز آروان با real-ip صحیح اعمال و بررسی شود.
- استقرار فعلی user پیش‌فرض Dockerfileها را نگه داشته است؛ کاهش سطح دسترسی container و اسکن بسته‌های سیستم‌عامل image قبل از راه‌اندازی فروش بازبینی شوند.
- برای توقف فقط Oosta از Compose همین پروژه با `stop web api postgres` استفاده شود. volume، secrets و backupها حذف نشوند؛ سایر استک‌ها متوقف نشوند. فایل Nginx این دامنه مستقل است. migration جدید روی DB واقعی rollback نشده است.
